# 0017 — CPU tile rasterizer, material resolution and golden policy

## Status
accepted

## Context
T04 froze `ICpuRasterizer`/`RasterRequest`/`RasterImage` (`thumbnail-provider/CpuRasterizer.h`)
and T13 wired `DefaultThumbnailDependencies::Render` to a stub returning
`UnsupportedRequiredFeature`, so `GetThumbnail` still failed after T14 landed the sampler. T02
prototyped and measured the CPU rasterizer (`thumbnail-spike/rasterizer/ThumbnailRasterizer.*`,
58.8 ms mesh / 185.9 ms points at 512 px 2x supersampling) and its hand-off explicitly said T15
must "replace the T02 prototype behind the same contract, not reuse it as-is". design/05 ("CPU
renderer") fixes resolution clamping, isometric framing, depth test, ambient + two lights, the
weighted-opaque transparency approximation, round point splats, linear-space downsample,
premultiplied BGRA and the ledger/deadline discipline. The frozen provider types (T14
`SampledGeometry`, `model_core::MaterialPayload`) carry more than the prototype's ad-hoc
`Triangle`/`Point`, and the family tasks (T21–T34) own material semantics.

## Decision
- The production rasterizer is `thumbnail-provider/CpuRasterizer.{h,cpp}`; the entry point
  `RenderCpuTileRaster(const RasterRequest&, RasterImage&)` and the thin `CpuTileRasterizer`
  adapter implement the frozen contract. It is PCH/COM/GDI-free and compiles into both the DLL
  and `Tests.Unit.exe` (`CpuRasterizerImpl.h` names it; `ThumbnailPipeline.cpp` calls it). The
  T02 prototype stays in `thumbnail-spike/` untouched.
- **Resolution and supersampling.** The raster is `size = min(cx, 512)` for nonzero `cx`; `cx`
  is only a hint and a larger request is clamped, never rejected. 2x internal supersampling is
  used only when `allowSupersample` is set **and** the cooperative deadline has at least 250 ms
  of remaining headroom (the prototype's cap render took ~186 ms at 2x); otherwise it falls back
  to 1x. `RasterRequest::allowSupersample=false` forces 1x. The returned `HBITMAP` therefore fits
  within `cx` in each dimension at the 32 px floor.
- **Material resolution.** A triangle's albedo is `vertexColor.rgb * baseColorFactor.rgb`;
  `alphaMode` selects Opaque (alpha 1), Mask (discard below `alphaCutoff`, else opaque) or Blend
  (the weighted-opaque approximation — blend toward a neutral frost by opacity and write an
  opaque, depth-testing result, so no sorting or OIT is required). `kMaterialFlagDoubleSided`
  controls backface culling, `emissiveFactor` is added after shading, and `kMaterialFlagUnlit`
  skips the light rig. `materialIndex` 0 or out of range selects `NeutralMaterial()`. Point
  splats use the same base-color modulate/alpha rules and are depth-tested with deterministic
  bounds-derived size.
- **Accounting and deadline.** Raster targets (`color` 4×f32/pixel, `depth` f32/pixel) and the
  output buffer are reserved against the caller's `AllocationLedger` before allocation; a charge
  that would cross the ceiling returns `ResourceLimit` (`ERROR_FILE_TOO_LARGE`) with a null image
  and allocates nothing. A null ledger disables accounting (unit-test convenience, matching the
  sampler). The cooperative deadline is polled every 2048 units of work; expiry returns
  `Cancelled` (`ERROR_TIMEOUT`) and leaves `out` empty.
- **Goldens.** `tests/unit/ProviderRasterizerTests.cpp` renders mesh/point/alpha scenes at
  32/64/256/512 px, stores lossless PAM `RGBA` goldens in `thumbnail-provider/goldens/`, and
  compares them with the tolerant perceptual metric from `testing-strategy.md` (mean absolute
  error ≤ 2.0, max outlier ≤ 48), never byte equality. The goldens are regenerated by the hidden
  case `x64\Release\Tests.Unit.exe "[write-goldens]"`.
- **Rejected:** reusing the prototype source (different input types, no material/ledger/deadline
  integration); a GPU/D3D path (out of scope by contract); true order-independent transparency
  (unnecessary at thumbnail size); inventing material semantics for the families here (T21–T34
  supply product-owned values).

## Consequences
- `GetThumbnail` now has a working render stage; only the family adapters (T21–T34) remain
  before a real call can complete. An empty `SampledGeometry` is still mapped to `BadFormat` by
  the pipeline, never a fabricated image.
- The provider DLL gains only CRT math imports from the rasterizer; the two-symbol `PRIVATE`
  export surface and the dependency-closure rule are unchanged (`[provider][scaffold]` green).
- `[provider][rasterizer]` (11 cases) covers clamping, determinism, premultiplication, the
  golden sizes plus alpha/point cases, masked-cutoff discard, weighted-opaque transparency, the
  depth test, deadline/ledger failure and the null-geometry path. A hidden `[rasterizer-perf]`
  case records the cap render time.
- T21–T34 must populate `MaterialPayload` meaningfully (base color, alpha mode/cutoff,
  double-sided/unlit/emissive) and keep vertex colors linear; the rasterizer will otherwise fall
  back to the neutral material. T02's `RasterizerSpike` remains only as spike evidence and is not
  part of the shipped provider.
