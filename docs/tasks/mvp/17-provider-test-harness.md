## Goal
Give every later adapter one repeatable harness: a COM host that activates the provider like the
Shell, renders and compares golden images, runs parallel apartments, and samples GDI/User/private-byte
leaks across repeated load/unload.

### Decisions / deviations
- **The golden path uses the linked real pipeline, not the DLL.** With every
  `CreateFamilyAdapter` case still `nullptr`, no COM call can render. The host
  therefore activates the DLL through the real COM sequence *and* renders the
  placeholder fixture through the shipped `RunThumbnailPipeline` + T14 sampler +
  T15 rasterizer compiled in — the production orchestration, never a copy. T21
  links its adapter into the host and registers a fixture; the same `[host][com]`
  case then observes a real bitmap without edits.
- **`[host][com]` accepts both outcomes.** A family returns `S_OK`/`WTSAT_ARGB`
  once its adapter is linked, or the `ERROR_NOT_SUPPORTED`/null-bitmap fallback
  while it is not, so the case stays valid as the registry fills in.
- **Leak loop also round-trips a DIB.** The unlinked provider creates no GDI
  object, so the cycle also renders the placeholder and creates/deletes its
  `CreatePremultipliedDib` HBITMAP, making the GDI check meaningful. Private-byte
  allowance (16 MiB) absorbs CRT allocator retention across 128 cycles.
- No product source changed; the DLL's two-symbol `PRIVATE` export surface and
  dependency closure are untouched.
