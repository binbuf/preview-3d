# T13 — HDR/EXR textures and environment assets

## Reusable facts

- **HDR decoder (product-owned).** `import-worker/src/RadianceHdrDecode.{h,cpp}`:
  `#?RADIANCE`/`#?RGBE`, one `FORMAT=32-bit_rle_rgbe`, `-Y <h> +X <w>` (signs
  and Y-then-X order validated), new-style per-channel RLE + flat RGBE.
  Rejects XYZE, X-first, old-style RLE, malformed headers, RLE overruns,
  truncation and all budgets. `DecodeRadianceHdrToLinear` is the environment
  path; `DecodeRadianceHdrImage` is the material path.
- **EXR decoder.** `import-worker/src/OpenExrDecode.{h,cpp}` compiles the
  repository-vendored `third_party/tinyexr/tinyexr.h` (pinned copy from the
  TinyUSDZ 0.9.1 closure) with `TINYEXR_USE_MINIZ=0` and system zlib. Supported:
  single-part scanline, non-tiled, non-deep; NONE/RLE/ZIPS/ZIP/PIZ; HALF/FLOAT,
  sampling 1; R/G/B/A or Y names (layered `layer.R` works), first-three/one-
  channel fallback. Reject tile/deep/multipart/UINT/other compression, bad
  data windows and budgets in the product preflight before tinyexr allocates.
- **Why not link TinyUSDZ's compiled tinyexr:** referencing its symbols from
  `tinyusdz_static.lib` pulled a BasisU transcoder object and produced ~50
  `LNK2005` collisions with `ktx.lib`. Vendoring the header and compiling it in
  our TU avoids that. Do not switch back to the archive symbol without testing.
- **Linear policy.** `HdrFloatDecode.{h,cpp}` holds `LinearRgbaImage`,
  `FinalizeLinearImage` and `DownscaleLinearRgba`. Color/emissive: Reinhard
  `c/(1+c)` at exposure 1.0 then the caller's sRGB transfer. Normal/data: clamp
  only, stay linear (normal maps are not tone-curved). Downscale is area-
  averaged in linear light to `maxDimension`, then `GenerateRasterMips`.
  Transient float cap: `max(maxDecodedBytes, 64 MiB)`.
- **No new PixelFormatId.** Everything reaches the wire as `RGBA8_UNORM`; the
  environment hook keeps linear float outside the Material chunk stream.
- **Environment API.** `import-worker/src/EnvironmentAssetDecode.{h,cpp}`:
  `LoadEnvironmentAsset(span<const byte>, EnvironmentAssetOptions)` returns
  `EnvironmentAsset{width,height,rgba float equirect}`. Bytes only, no path or
  URI. Defaults 64 MiB encoded / 256 MiB decoded float / 64 Mi pixels / 4096
  max dimension. T14's procedural Studio environment needs no decode.
- **Sniff/allowlist.** `SniffedImageFormat::Hdr/Exr`; magic `#?RADIANCE`/`#?RGBE`
  and `76 2F 31 01`. `HasDecodableImageExtension` and
  `SidecarPathResolver::IsImageExtension` accept `.hdr`/`.exr`; also
  `UsdAdapter::ImageExtensionMatches` and the Assimp adapter's local allowlist
  (which gained `.tga`/`.dds` too, aligning it with T12).
- **Dispatch sites updated:** `GltfAdapter`, `ObjAdapter`, `FbxAdapter`,
  `UsdAdapter`, `AssimpTextureDecode`, `compatibility-host/src/OpenUsdHost`.
- **Fixtures.** `tests/fixtures/textures/` generated by
  `python tests/fixtures/textures/generate_textures.py`: HDR color/flat and
  malformed/truncated variants; EXR color (HALF ZIP), float RGBA (NONE),
  normal, roughness (Y ZIPS), tiled/deep/multipart/PIZ/UINT/truncated rejects;
  `exr/` OBJ package using EXR albedo+normal; `exr-gltf/` glTF sidecar
  package; `bad-exr/` truncated fallback.
  Known values: HDR/EXR (0,0) linear 4.0/0.5/0.25 -> sRGB RGBA8
  231/156/124/255; normal -> 128/128/255; roughness 0.25 -> 64.
- **Tests.** `tests/import-isolation/TextureHdrExrTests.cpp` tags
  `[texture-hdr]`, `[texture-exr]` (decode, format, linear/sRGB, fallback,
  budgets, cancellation, environment hook, OBJ package).
- **Fuzz.** `GltfFuzz` domains 9 = HDR, 10 = EXR; `prepare_gltf_seeds.py`
  materializes 61 seeds (16 new HDR/EXR seeds).

## Gotchas

- `FreeEXRHeader`/`FreeEXRImage` must only run after a *successful* tinyexr
  parse/load; calling them after a failed load double-freed and crashed with
  `STATUS_HEAP_CORRUPTION` (0xC0000374). The guards track an `owned` flag.
- tinyexr needs `#include <zlib.h>` before the header when `TINYEXR_USE_MINIZ=0`;
  the header itself does not include it.
- The tinyexr implementation emits C4245 etc. under /WX; the include is wrapped
  in a local `#pragma warning(disable: ...)` push/pop.
- `HdrFloatDecode.h` transient budget is intentionally larger than the RGBA8
  output budget (4 floats/texel vs 4 bytes). A 4K float source can still be
  rejected; that is a soft fallback, not a model failure.
- Catch2 test filters split commas: run the reject case with `\,` escapes or by
  a unique no-comma substring.
- `Preview3DOpenUsdCore.vcxproj` needed an explicit `/t:Rebuild` in this session
  to observe new source files; a normal build reported "up-to-date".

## Follow-ups

- T14 can consume `LoadEnvironmentAsset` for an embedded HDRI; the preferred
  procedural Studio environment needs no decoder.
- Float/BC6H GPU texture formats remain deferred. If a later task samples HDR
  textures directly, it must add `RGBA16_FLOAT`/`BC6H_UF16` to
  `PixelFormatId`, `PixelFormatBlockInfo`, `ComputeImagePixelBytes`,
  `DxgiFormatFor`, the shared-section validator and tests, and prove FL11_0.
- EXR B44/B44A/DWAA/DWAB and old-style Radiance RLE are rejected; add bounded
  implementations only if real fixtures justify them.
- `occlusionStrength` remains unrepresented (T12 follow-up).
- TinyUSDZ's own vendored tinyexr notice was added to
  `packaging/vcpkg-ports/tinyusdz/VENDORED-NOTICES.txt`; keep it if the port is
  upgraded.
