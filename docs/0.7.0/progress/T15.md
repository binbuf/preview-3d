# T15 — HDR target, exposure, background and presets

## Reusable facts

- **Pure module.** `interactive-viewer/src/render/Presentation.{h,cpp}` owns the
  tone curves, exposure clamp, background modes and material-aware preset
  mapping. It has no Direct3D dependency, so `Tests.Unit` exercises the exact
  functions the renderer uses. `SummarizeMaterials` scans at most
  `kMaterialScanCap` (4096) records; `baseColorImageChunkIds` is an optional,
  index-aligned span because `MaterialPayload` has no texture slots.
- **HDR target.** `D3D12ViewerPath` creates `R16G16B16A16_FLOAT` `sceneColor`
  with one RTV heap and one shader-visible SRV heap in
  `CreateSceneColorTarget` (called from `CreateDepthBuffer`, so resize and
  device recovery rebuild it). It is added to `AccountedAllocationBytes` as
  `sceneColorAllocationBytes`.
- **Resolve pass.** `CreateResolvePipeline` compiles
  `kResolveVertexShaderSource`/`kResolvePixelShaderSource` to vs_5_1/ps_5_1.
  The root signature is 8 32-bit constants at b0 plus one SRV table (t0) and a
  linear clamp sampler (s0). `ResolveSceneToBackBuffer` transitions HDR
  RT -> PIXEL_SHADER_RESOURCE, binds the R8G8B8A8_UNORM back-buffer RTV, draws
  a 3-vertex fullscreen triangle, then transitions back to RENDER_TARGET.
  Object pipelines all use `kSceneColorFormat` for RTVFormats[0]; the pick MRT
  stays R32_UINT.
- **Color ordering.** Object shaders now emit linear HDR
  (`float4(max(color,0.0f), base.a)`). The resolve composites background in
  linear, applies exposure, tone curve and sRGB. The helper `NeutralToneMap`
  remains in the textured shader only to keep the T14 source-contract tests
  green; `PSMain` does not call it. Dark/mid-grey clear alpha 1; transparent
  and checker clear zero and the resolve preserves `scene.a`.
- **Backgrounds.** `BackgroundLinear`: Dark #1C1C1E, MidGrey linear 0.21,
  Transparent/Checker zero alpha. Checker shades are 0.10/0.18 linear, cell
  12 px, computed in `PSMain` from `SV_POSITION`.
- **Presets.** `PresentationPreset` = StudioPbr, StudioCad, ScanSculpt,
  Transparent, PointCloud. `SelectPresentationPreset` priority: point-only /
  catalog PointCloud -> CAD format / catalog StudioCad -> majority
  alpha/transmission -> dense untextured scan (>= 50k triangles) -> StudioPbr.
  Preset settings supply environment intensity, key/fill/rim scales, exposure,
  background and grid. `OverlayInfo` carries them to the render thread.
- **App wiring.** `Preview3D.cpp` seeds exposure/background/tone map from
  `ViewerSettings` (now version 6), applies presets once per terminal upload
  from `RenderUploadResult::materialSummary`, and pins a manual preset/lighting
  choice through `presentationOverridden`. Keyboard: `[`/`]` exposure,
  `\` background, `` ` `` tone curve.
- **Test-control fields** (`WM_APP+104`, Debug/`--app-smoke`): 89 query preset,
  90 select preset, 91/92 exposure bits, 93/94 background, 95/96 tone map,
  97/98 studio intensity, 99/100 mean/p95 frame ms (double bits).
- **Screenshot lane.** `tests/app-smoke/studio-presets.py` reuses the T14
  capture path, generates a six-sphere and a transparent-sphere GLB, forces each
  preset, captures six PNGs, writes `studio-presets-golden.json`, and records
  MAE (0.06) + global SSIM (0.90) tolerances plus frame/GPU/private bytes.
  Evidence lives in `docs/0.7.0/progress/T15-evidence/`.

## Gotchas

- `RenderClearFrame` must clear the HDR target and run the resolve too; clearing
  the back buffer directly leaves the idle background bypassing exposure/tone
  map and the checker.
- `ResolveSceneToBackBuffer` sets a full-window viewport/scissor after the scene
  pass. Do not restore the inset viewport before the overlay; D2D owns its own
  clip.
- `SendMessage` returns a signed `LRESULT`; field 99/100 are double bit patterns,
  so unpack as `<d`, not `<f`.
- The tag filter is `[tonemap]`/`[studio-presets]`. The existing `[studio-ibl]`
  source-string test still expects `NeutralToneMap` and `startCompression` in
  the textured shader text, so keep the helper declaration even though the
  object pass no longer calls it.
- `tests/app-smoke/recovery.py` fails before its device-removal step because its
  `unsupported.3mf` expectation predates T10b; use the injected-removal check
  above or fix that script separately.
