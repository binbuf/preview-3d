# T05 - glTF required-extension compatibility

## Reusable facts

- Policy table: `import-worker/src/GltfAdapter.cpp`, anonymous namespace near
  `IsSupportedExtension`. One row per extension: `name`, `GltfExtensionClass`,
  `fastgltf::Extensions` mask bit (or `None`), `adapterSupported` (false means a
  compatibility record is emitted).
- Enabled in the fastgltf mask: Draco, basisu, texture transform, quantization,
  meshopt, WebP, unlit, transmission, ior, pbrSpecularGlossiness, clearcoat,
  sheen, specular, iridescence, anisotropy, volume, dispersion,
  diffuse_transmission, emissive_strength, variants, lights_punctual.
  `MSFT_texture_dds` stays disabled until T12.
- Classes: `Core`, `GeometryCritical`, `TextureCritical`, `Visual`, `Scene`,
  `Instance`, `Unknown`.
- Never filtered: `KHR_draco_mesh_compression`, `EXT_meshopt_compression`,
  `KHR_mesh_quantization`, `KHR_implicit_shapes`, `KHR_accessor_float64`.
  Those last two have no parser bit, so a required use returns
  `UnsupportedRequiredFeature` before parsing.
- Filterable when not parser-enabled: anything in `TextureCritical`, `Visual`,
  `Scene`, `Instance`, plus every unknown name. `EXT_mesh_gpu_instancing` is
  deliberately filtered/one-instance; full expansion is out of scope.
- Pre-scan uses simdjson in the existing JSON preflight and stores
  `requiredExtensionNames`. The filtered JSON rewrite is bounded text work in
  `BuildFilteredRequiredExtensions` / `BuildFilteredGltfSource`: it edits only the
  root `extensionsRequired` contents and pads with spaces, so a GLB keeps its
  header/BIN offsets. `extensionsUsed` is never edited.
- Important GLB retry gotcha: `MappedGetter::bin` must point into the filtered
  copy at `binOffset` for the retry, otherwise `GltfDataGetter::read` tries to
  copy BIN bytes back through the read-only mapping and the worker dies without
  replying. The parser object must also outlive the asset (fastgltf may allocate
  from the parser pool).
- Reporting helper: `BuildGltfCompatibilityReport` is used by both the streaming
  and single-section paths. Visual/instance/unknown -> `Degraded`; scene/core ->
  `Ignored`; fully supported names emit nothing. The legacy
  `optionalFeatureWarnings` count is still incremented once per unsupported name.
- Fixtures are in `interactive-viewer/test-assets/`:
  `required-clearcoat.gltf`, `required-specular.gltf`,
  `required-emissive-strength.gltf`, `unknown-required.gltf`,
  `required-geometry-unknown.gltf`, `required-draco-bad.glb` (a copy of
  `draco_triangle.glb` with its BIN payload zeroed).
- Tests are in `tests/import-isolation/GltfImportTests.cpp` under
  `[gltf-extensions]`; the old "unrecognized extension is rejected" case now
  asserts degraded core geometry. `RecoveryTests.cpp` likewise expects
  `EmptyGeometry` for an unknown required name with no scene and keeps
  `UnsupportedRequiredFeature` for `KHR_implicit_shapes`.

## Gotchas

- `asset.extensionsUsed` is `std::vector<std::pmr::string>`; compare it with
  `std::string_view` (the report helper does) rather than `std::find` against
  `std::string`.
- A filtered `.gltf` retry reuses the same source bytes; only a GLB needs the
  full-container copy.
- No new numeric limit was introduced. Required-name count reuses
  `kTierAObjectLimit`; copy size stays under the existing 32 MiB metadata cap.
