# T07 — STEP tolerance and import quality

## Reusable facts

- **Profile version is now 6.** `StepTessellationProfile.h`:
  `StepTessellationQuality { Draft=0, Balanced=1, Full=2, Coarse=Draft,
  Display=Balanced }`; `fullRelativeDeflection = 0.001`,
  `fullAngularDeflection = 0.12`. Balanced = old display values; Draft = old
  coarse values. Absolute window/budgets unchanged.
- **Request quality bits** in `shared/model-core/include/model_core/
  ControlProtocol.h`: `kImportRequestStepQualityDraft = 1u << 9`,
  `kImportRequestStepQualityFull = 1u << 10`, mask = both. Both set is a
  protocol violation. `StepImportQualityFromFlags` / `StepImportQualityFlags`
  are the pure mapping. Broker field:
  `ImportSessionRequest::stepImportQuality`.
- **Cache identity:** `step_host::StepImporterCacheIdentity(quality)` returns
  `(kStepImporterVersion << 2) | quality`. `kStepImporterVersion = 1 +
  kStepTessellationProfileVersion` (= 7).
- **Unit policy:** `ResolveStepLengthUnit(authoredLengthUnitEntities,
  reportedMetersPerUnit)` in `StepTessellationProfile.h`. Zero/unusable →
  0.001 + `assumedMillimetres`; >1 authored → `contradictory` and the reader's
  first/dominant factor; >1e12 → `overflow` (adapter returns
  `UnsupportedRequiredFeature`). `metersPerUnit` in the scene for the mm
  fixtures is `0.001`.
- **Counting units:** do not rely on `STEPControl_Reader::FileUnits` to detect
  contradictions; it collapses a context's units. `CountAuthoredLengthUnits`
  in `StepXdeAdapter.cpp` walks the interface model for
  `StepBasic_SiUnitAndLengthUnit`, `StepBasic_ConversionBasedUnitAndLengthUnit`
  and `StepBasic_LengthUnit`. OCCT complex units use multiple inheritance, so
  `IsKind(Standard_Type(StepBasic_LengthUnit))` alone misses them.
- **External documents:** `StepPart21Preflight` counts only entity names via
  `EntityName(text)` (skips comments/strings). Default `maxExternalDocuments`
  is 64. Provider `StepFamilyAdapter.cpp` explicitly sets `0`, so its
  `ExternalDocumentRejected()` behavior/tests stay valid.
- **Compatibility feature IDs** (3000 range, `model_core/Compatibility.h`):
  3000 external unresolved (Degraded), 3001 unit assumed mm (Degraded),
  3002 contradictory units (Degraded), 3003 bounded repair (Degraded),
  3004 unmeshed definition (Ignored). Host text added in
  `interactive-viewer/src/app/CompatibilityText.h` with English `Loc`
  fallbacks; packs were not regenerated.
- **Repair:** `StepHealingPolicy::BoundedRepairOnFailure`, budget
  `StepRepairBudget{20'000 faces, 200'000 edges, 30'000 ms}`. Runs only when
  `chunks.empty() && mesher.repairEligible()`; `repairEligible` is false for
  time/face/edge/triangle budget failures and cancellation. `ShapeFix_Shape`
  result must pass `BRepCheck_Analyzer` and still emit geometry. A repaired
  definition increments the 3003 count; otherwise the original typed result is
  preserved.
- **Do not check `BRepMesh_IncrementalMesh::IsDone()` as a hard failure.** An
  authored AP242 tessellated-only representation already carries triangulation;
  requiring `IsDone()` regressed `tessellated_only_ap242.stp`. Extraction is the
  authority.
- **Fixtures** are generated by
  `tests/fixtures/stp-spike/GenerateStepToleranceFixtures.py` from
  `part_ap214.stp` / `face_color_ap214.stp`; rerun it rather than hand-editing.
  `repair_needed_ap214.stp` is a single face with an empty edge loop (repair is
  attempted, `EmptyGeometry` is preserved). `unrepairable_ap214.stp` removes a
  referenced face entity.

## Gotchas

- `StepQualificationTests` and `StepProtocolTests` previously asserted external
  declarations were rejected; T07 changed those to `Ok` with a count. Keep the
  provider's explicit cap-0 behavior in mind when reading scanner tests.
- `StepPerformanceTests` pins `kStepTessellationProfileVersion == 6`; bump both
  it and the profile comment on any further semantic change.
- `CompatibilityText.h` has unusual indentation in places; match exact text when
  editing. `CompatibilityTests` checks `kFeatureIdStepMax` (3999) still has no
  text.
