# T16 — Ground contact shadow and ambient occlusion

## Reusable facts

- **Chosen path: analytic soft contact footprint, no extra pass.** ADR-0072
  records the tradeoff against a 1024/2048 PCF shadow map. The renderer has no
  shadow target, depth pass or new GPU allocation.
- **Pure math.** `interactive-viewer/src/render/GroundShadow.{h,cpp}` owns
  `TransformBounds`, `PlaceGroundPlane`, `ProjectShadow`, `ShadowMask`,
  `OcclusionFactor` and `BuildConstants`. `[ground-shadow]` unit tests use the
  same functions the GPU layer mirrors.
- **Placement.** Ground z = `worldBounds.min.z - 0.0015 * radius`; the grid
  stays at `worldBounds.min.z - 0.012 * radius`, so the layers cannot z-fight.
  Ground is placed after the active `GroundAxisTransform`, so turning the model
  also moves the plane.
- **Projection.** Stable world key `(0.45, -0.55, 0.70)`; eight bounds corners
  are projected along it, then the footprint is biased 15 % back toward the
  base (`kContactBias`) and given a 0.60 x radius soft rim. Opacity 0.78,
  softness 0.50. Light elevation clamps to 0.08 and the footprint to 6 x radius.
- **GPU layer.** `kGroundVertexShaderSource` draws a six-vertex quad from
  `SV_VertexID`; `kGroundPixelShaderSource` mirrors `ShadowMask` and composites
  straight alpha into the linear HDR target. It is drawn before the grid and
  the model, writes no depth, and is completely independent of the grid
  pipeline. `D3D12ViewerPath::GroundPixelShaderSource()` exposes the text for a
  no-GPU source/compile test.
- **Root signature.** The compact root signature's b1 (register 1) changed from
  vertex-only to `D3D12_SHADER_VISIBILITY_ALL` so the ground pixel shader can
  read its four float4s. `SetGraphicsRoot32BitConstants(1, 16, ...)`.
- **ORM AO.** `OcclusionFactor(sample, strength) = saturate(1 + strength *
  (sample - 1))`; absent map samples 1.0. AO scales indirect diffuse, IBL
  reflection and ambient only. All three `EvaluateLight` direct calls remain
  unoccluded. `MaterialPayload` still has no `occlusionStrength`, so the shader
  passes 1.0 (glTF default).
- **Preset/toggle.** `PresetSettings::shadowEnabled`: CAD/PBR/Scan true,
  Transparent/Point cloud false. `ResolveShadowVisible(overridden, current,
  presetDefault)` lets `H`/the More menu pin the toggle across preset applies.
  `ViewerSettings` v7 persists `groundShadowEnabled`.
- **Test-control fields** (`WM_APP+104`, Debug/`--app-smoke`): 101 query
  shadow, 102 set shadow, 103 query grid, 104 set grid. The handler gate is now
  `wParam > 104`, not 100.
- **Evidence lane.** `tests/app-smoke/ground-shadow.py` generates a binary STL
  box, a sphere GLB, a transparent sphere and an ASCII PLY point cloud, drives
  the presets/toggles, writes `ground-shadow-golden.json` + report, and asserts
  MAE 0.06 / global SSIM 0.90 plus a 0.0005 change threshold for the subtle grid
  strokes. Evidence is in `docs/0.7.0/progress/T16-evidence/`.
- **Keyboard/help.** `H` accelerator, More menu item with check state,
  `controls.frameResetDetail` text and `en.json` keys (`menu.groundShadow`,
  `hud.shadow*`, `a11y.shadow*`).

## Gotchas

- `WM_APP+104` rejects every field above its gate; adding 101-104 required
  raising `wParam > 100` to `> 104`.
- The ground layer is built from `modelBoundsMin/Max` in the **source** frame
  and must apply `GroundAxisTransform` exactly like the grid; do not feed it
  already-transformed camera bounds.
- `Constants` is four `float4`s. The root signature was already 33 DWORDs; only
  its visibility needed changing.
- The grid strokes are subtle: image-change assertions for grid-on vs grid-off
  need a threshold below 0.002 (0.0005 works, shadow-on vs off is ~0.02).
- Debug screenshots are ~1258x849; the gallery preview scales them, so a
  contact ring that looks faint in the thumbnail is a real dark band at full
  size. The sculpt capture makes the effect obvious.
- The RC file is UTF-16 LE with a BOM; edit it with a Unicode-aware writer or
  the build loses the accelerator table.

## Follow-ups

- SSAO remains deferred. Add it only as a non-default quality option once the
  HDR path exposes scene depth/normals and the contact shadow never depends on
  it.
- A future proper shadow-map slice can replace the analytic quad behind
  `GroundShadowConstants` and the same preset/toggle contract (1024/2048 depth,
  PCF, normal bias).
- Add `occlusionStrength` to the material contract when the wire payload can
  grow; the shader helper already takes the strength parameter.
- If a user enables the shadow on the Transparent preset, the ground quad makes
  the captured alpha opaque. Either keep the shadow disabled for capture or
  write ground alpha as premultiplied coverage in a later transparency task.
- The analytic key is world-fixed rather than the camera-relative direct rig;
  align them if a later lighting task makes the key physically authoritative.
