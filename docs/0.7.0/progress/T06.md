# T06 — Per-format presentation defaults and orientation

## Reusable facts

- Catalog profile enum: `shared/model-core/include/model_core/FormatCatalog.h`
  now has `PresentationProfile::Default | StudioPbr | StudioCad | PointCloud`.
  Families: glTF/GLB/FBX/OBJ/PLY-mesh/USD → `StudioPbr`; STL(+ASCII)/3MF/STEP →
  `StudioCad`. OBJ `defaultUpAxis` is `Y`, units `Unspecified`.
- Pure selection: `model_core::ResolvePresentationProfile(descriptor,
  {pointCount, triangleCount})`. Only a PLY family with `pointCount > 0` and
  `triangleCount == 0` becomes `PointCloud`; every other family returns its
  declared profile. Do not add a second viewer switch for this decision.
- Broker policy: `shared/model-core/include/model_core/SceneMetadataRules.h`
  `SceneUnitsAndUpAxisAllowed(format, up, metersPerUnit)`. `SharedSectionValidator.cpp`
  calls it. OBJ accepts Y or legacy Unknown with metres == 0; X/Z or authored
  metres are rejected. Other format rules match the previous inline block.
- OBJ adapter now writes `metadata.upAxis = UpAxisId::Y`; no geometry rotation
  is baked, so `GroundAxisTransform` still corrects Y→Z and the toolbar/hide
  native-orientation overrides keep working.
- FBX: pinned ufbx 0.23.0 exposes `settings.axes.up` and
  `settings.original_unit_meters` even after target-axis normalization, but the
  wire still carries normalized Y/1.0. The adapter reads the authored values
  (for documentation) and deliberately does not transmit them. Do not just
  switch metadata to authored values without also changing
  `SceneUnitsAndUpAxisAllowed` and every FBX fixture/test that expects Y/1.0.
- Viewer apply point: `Preview3D.cpp` `kRenderUploadCompleteMessage`, first
  `uploaded->terminal && !uploaded->refinement` for a new
  `uploaded->path`. `presentationSourcePath` suppresses reload re-application;
  `presentationOverridden` is set by `SetLightingMode` and `ToggleGrid` so a
  user choice wins for the session. `ApplyPresentationProfile` maps:
  StudioPbr → `LightingMode::Studio` + grid; StudioCad → `LightingMode::Clay`
  + grid; PointCloud → `LightingMode::Studio` (splat shader is unlit) + no grid.
- Backdrop tints live in `D3D12ViewerPath.cpp` `PresentationClearColor` and
  `Renderer.cpp`; they only affect the clear color.
- Info panel: `BuildInfoPanelSections(metadata, showNativeOrientation,
  groundAxis, preset = Default)` appends a `Presentation` section LAST, so
  existing tests that index `[5]` for Scene Data are unaffected. If `preset`
  is Default it re-resolves from the catalog for display.
- Localization: new keys `presentation.*` were appended to every pack with the
  English fallback. `LocalizationTests` and `[presentation]` pass.

## Gotchas

- `Tests.Unit` does not link `SharedSectionValidator.cpp`; that is why the
  policy lives in a header-only pure function and is tested directly.
- A PLY with both points and triangles is a mesh: never force PointCloud on
  triangleCount > 0.
- `FindBySourceFormatId` returns the ASCII PLY/STL descriptors too, so
  `AsciiPly` still resolves through the `Ply` family.
- `BuildInfoPanelSections` uses `Loc` keys; don't pass temporary `c_str()` keys
  (see T02 gotcha).
