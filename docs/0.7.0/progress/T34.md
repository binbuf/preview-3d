## T34b fixes

1. **Shared OS-metadata filter.** `corpus.is_corpus_entry(name)` excludes
   leading-dot entries and Windows directory metadata (`desktop.ini`,
   `Thumbs.db`, `ehthumbs*.db`, `Thumbs.db:encryptable`, `$RECYCLE.BIN`,
   `System Volume Information`). Both the inventory and the external audit use
   it, so `desktop.ini` no longer becomes `unaccounted corpus root entries`.
   Three focused checks in the lane build a temp root with `.git`, metadata
   files and `Cube.STL`: the real entry is still counted, unaccounted is `[]`,
   and an audit that omits `Cube.STL` still reports it. No per-asset
   exceptions and no `maxEntryBytes` change. The rule is recorded in
   `docs/design/adr/0091-corpus-root-metadata-accounting.md`.
2. **Correct Release probe.** A Release binary rejects `--app-smoke` with the
   ordinary unknown-option exit (2) and has no `WM_APP+104` handler. The probe
   now asserts both: `--app-smoke` exit != 0, then a normal Release launch
   answers fields 0/105/107/300 with 0. Do not use `viewer.Viewer` for a
   Release process; it always passes `--app-smoke`.

## Reusable facts / gotchas

- **Do not run the gate in the background.** The T34 first session idled for
  about seven hours before launching it. Run the exact command in the
  foreground with a long explicit timeout and wait once.
- **The review gate reads the file before the report is written.**
  `verify.py` marks review `recorded` when `review/T34-review.json` has
  `imagesInspected` and `reviewer.identity`. If the file is missing, the gate
  fails with `image review record missing or empty`; this is not a rendering
  failure.
- **`--fast` never proves T34.** It drops the external corpus, F3D references
  and review gate. Capture-only reports `status: capture-only`, not `pass`.
- **The local corpus is restricted.** It lives at
  `D:/repos/binbuf/preview-3d-test-models`; models, screenshots and F3D renders
  stay under `TestResults/` and must not be committed.
- **`desktop.ini` is hidden/attributed but still `iterdir()`-visible.** A plain
  extension filter is not enough; the shape has to be name-based and shared.
- **`seed_for()` resolves `rootName`, not the seed alias,** for T34 profiles.
  Earlier profiles still use `seedAssets`.
- **Profile sizes drive the dispositions.** The five `maxEntryBytes: 1`
  assets are intentionally typed dispositions; do not "fix" them by raising
  the cap.
- **Mint FBX failure is a disposition, not a skipped image.** It keeps an
  `external-mint-failed-load.png`; that image is not a successful capture.
- **F3D 3.5.0 is not a target.** Its shipped preset is DPI-aware (1920x1350
  from a 1280x900 request) and its Camera lens is a pale gray disk.
