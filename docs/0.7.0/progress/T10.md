# T10 — Bounded Assimp compatibility adapter

## Reusable facts

- **Dependency:** `assimp` 6.0.4#3 from the pinned vcpkg baseline, plus its
  transitive closure (`jhasse-poly2tri`, `kubazip`, `minizip`, `polyclipping`,
  `pugixml`, `rapidjson`, `stb`, `utfcpp`). `pugixml` is also a direct root
  dependency because the adapter uses it as the XML admission parser. Static
  closure only; the worker imports no upstream DLL.
- **Overlay port:** `packaging/vcpkg-ports/assimp/` copies the baseline port and
  adds `fix-x3d-empty-node-list.patch` (Assimp 6.0.4 called `front()` on an
  empty node list when its own X3D tokenizer rejected a document that pugixml
  accepted). Reinstall with the manifest install root used by MSBuild:
  `--x-install-root=vcpkg_installed\x64-windows-static-md` (vcpkg appends the
  triplet). Installing into `vcpkg_installed` alone updates a different tree
  and the build keeps linking the stale nested install.
- **Wire identities (append-only):** `SourceFormatId::Dae=18`, `ThreeDs=19`,
  `Dxf=20`, `DirectX=21`, `Off=22`, `Amf=23`, `X3d=24`.
  Catalog `FormatId` is the same for those seven; `Dxf=25`/`DirectX=26` are new
  catalog-only ids because T02 had not reserved them. `FormatId::Vrml=23`
  remains reserved with no descriptor.
- **Broker route:** `ImportFormat::Assimp`, opcode
  `StartAssimpImportFromFile=23`, request `ParseAssimpFileRequest` (56 bytes)
  with a closed `AssimpFormat` discriminator. `ImportSessionRequest` carries
  `assimpFormat` and the `assimpTinyLimitsForTesting` seam. The broker maps the
  expected wire id from that discriminator and treats every Assimp source
  format as Tier B (no coarse proxy/detail).
- **Admission before Assimp:** `import-worker/src/AssimpAdapter.cpp`
  - all text formats reject C0/DEL control bytes;
  - DAE/AMF/X3D are parsed as a bounded pugixml DOM (128 MiB cap) and require
    their root element (`COLLADA`/`amf`/`X3D`); DAE count/stride/offset
    attributes and `float_array`/`int_array`/`vcount`/`p` token lists are
    bounded; X3D index attributes (`coordIndex`, `index`, `colorIndex`,
    `normalIndex`, `texCoordIndex`) must be signed-integer token lists of
    `-1`-separated faces, and `point`/`color`/`normal` must be numeric tokens;
  - ASCII OFF is structurally walked (header counts, every vertex number, every
    face's corner count and indices) with the object/material/triangle/vertex
    caps;
  - 3DS requires the `MAIN3DS` (0x4D4D) chunk magic and a fitting declared
    length.
  - `XmlAdmission` returns `ResourceLimit` above 128 MiB, otherwise
    `MalformedData` on any structural fault.
- **IOSystem:** `BrokerIOSystem` implements `Assimp::IOSystem` over the broker
  callback. `Exists` only accepts a safe relative image extension and never
  touches the broker; `Open` rejects non-`rb` modes, absolute/rooted/UNC/device
  paths, `..`, `:`/ADS/URL, control bytes and non-image extensions, then asks
  the broker once per reference. `ImportContext::FetchSidecar` caches both
  success and failure, so material texture resolution and Assimp's own opens
  share one sidecar request. Images only: png/jpg/jpeg/bmp/tif/tiff/webp/ktx2.
- **Assimp configuration:** `aiProcess_Triangulate`,
  `JoinIdenticalVertices`, `GenNormals`, `SortByPType`,
  `ValidateDataStructure`; no animation evaluation, caches, plug-ins, writes or
  default IOSystem. `ReadFileFromMemory` uses the format hint, but Assimp may
  still fall back to signature detection if the hinted importer rejects the
  input; product admission is what keeps the accepted shapes bounded.
- **Normalization:** world-space triangles per mesh/material; `meshId`/`nodeId`
  are stable scene indices; materials are de-duplicated by a payload+image-id
  key; missing textures use the same deterministic checker/neutral fallback as
  OBJ and emit a bounded `TextureWarning`/`ImportStatus` pair.
- **Metadata:** no verifiable unit, so `metersPerUnit=0`. Up axes: DAE/Y,
  3DS/Z, DXF/Z, DirectX/Y, OFF/Y, AMF/Z, X3D/Y. `SceneMetadataRules` accepts
  the declared axis (or `Unknown`) and only zero units.
- **Catalog:** seven descriptors with `ImporterKind::AssimpCompat`,
  `ThumbnailFamily::None`, `CapabilityFlags::Sidecars` only where the format can
  reference textures. `IsImportableFormat` now includes `AssimpCompat`.
  `ProgIdForFamily` adds DAE/3DS/DXF/DirectX/OFF/AMF/X3D progids; the NSIS
  installer registers/unregisters all seven and deletes the new license files.
- **Fixtures:** `tests/fixtures/assimp-spike/` generated by
  `generate_fixtures.py`: positive DAE/3DS/OFF/AMF/X3D/X/DXF, missing texture,
  traversal texture, truncated DAE/3DS, malformed OFF/AMF, and 300-triangle
  over-budget OFF. All are repository-owned primitives; no third-party license.
- **Tests:** `tests/import-isolation/AssimpImportTests.cpp`, tag `[assimp]`.
  Positive all seven formats; missing texture degraded; traversal
  `UnsafeReference`; malformed/truncated typed failures; tiny-cap
  `ResourceLimit`; sidecar-request cap. `Tests.Unit`
  `[format-catalog][assimp]` and `[presentation]` cover catalog identity, wire
  ids and unit/axis rules.
- **Fuzz:** `tests/fuzz/AssimpFuzz.{cpp,vcxproj}` + `AssimpFuzzStub.cpp`
  (texture decoder stub) + `prepare_assimp_seeds.py`; seeds are one format byte
  plus the fixture. Wire it into the CI `fuzz-smoke` matrix as target
  `Assimp`. ASAN needs
  `_DISABLE_STRING_ANNOTATION;_DISABLE_VECTOR_ANNOTATION;_DISABLE_OPTIONAL_ANNOTATION`
  because the vcpkg Assimp archive has no STL sanitizer annotations.

## Gotchas

- The MSBuild vcpkg root is `vcpkg_installed\x64-windows-static-md` and vcpkg
  appends the triplet, producing
  `vcpkg_installed\x64-windows-static-md\x64-windows-static-md`. Installing to
  the outer `vcpkg_installed` does not update what the build links.
- Assimp's X3D importer must not be trusted on XML that pugixml accepts; the
  overlay patch is required, and the product XML admission still rejects the
  malformed declarations that reach it. A malformed `coordIndex` attribute
  (floats/negative face counts) reached a double-free in
  `X3DGeoHelper::coordIdx_str2faces_arr`; index-token validation rejects it.
- A malformed DAE numeric attribute (`offset="1$..."`) can drive Assimp into
  unbounded allocation. Keep the DAE attribute/token admission checks before
  calling Assimp.
- The OFF parser can hang on inconsistent header/vertex counts, so
  `OffAdmission` walks the whole token graph instead of trusting the header.
- `new (std::nothrow)` on an Assimp heap-derived class triggers C4291
  (warnings are errors); use ordinary `new` inside the adapter's try block.
- `Assimp::IOStream`/`IOSystem` method signatures need the `Assimp::` prefix on
  return/parameter types in a derived class.
- The Assimp fuzz target cannot use the default STL ASAN annotations because
  the vcpkg archive was built without them; the disable macros above are
  deliberate. libFuzzer disables leak detection after mutations because Assimp
  keeps process-global state.
- `Prepare-AssimpSeeds` now removes stale files from the target seed directory;
  otherwise old crash inputs silently become corpus seeds.

## Follow-ups

- Consider a native DXF adapter: Assimp's DXF support is only 3DFACE/polyline.
- Assimp's hinted importer may fall back to signature detection. If a later
  task needs a hard "one importer only" guarantee, add a product importer
  allowlist or a dedicated Assimp build split per format.
- Add thumbnail-family support only after deciding whether the provider may
  link Assimp; this task deliberately leaves `ThumbnailFamily::None`.
- The X3D empty-node-list patch should be rechecked when the vcpkg baseline
  moves past Assimp 6.0.4; drop the overlay patch if upstream fixes it.
