# T20 - deterministic visual comparison harness and observed baseline

## Reusable facts

- **Wrapper:** `python tests/render-quality/verify.py --task T20 --configuration Debug --output TestResults/render-quality/T20`.
  It builds `Preview3D` Debug by default (`--no-build` to skip), runs negative
  contract tests, captures, renders F3D references and compares accepted
  regression references. Exit code 1 on any failure.
- **Bootstrap/research:** `--capture-only` collects candidates and skips
  comparison. It is not a passing verification lane.
- **Profiles:** `tests/render-quality/profiles/TNN.json`. T20 registers generated
  sphere-grid/glass-reference/STL-box fixtures, Car/Camera/microscope/STL
  external cases, close-ups and an orbit. Later tasks add a profile, not code.
- **Promotion:** `python tests/render-quality/compare.py --case ... --candidate ...
  --captures ... --reason ... --reviewer ... --review <review.json>`. Ordinary
  verification never writes `baselines/accepted/`.
- **Review:** `tests/render-quality/review/T20-review.json`; image-capable agent
  read the PNGs. Local Symphony vision is disabled and provider settings were not
  changed.
- **Accepted refs:** 15 generated-fixture cases in
  `tests/render-quality/baselines/accepted/`. Observed baseline metadata (53
  cases) is `tests/render-quality/baselines/observed/T20/observed.json`.
  External images stay under ignored `TestResults/`.
- **Debug control fields** (WM_APP+104, only when `--app-smoke`):
  - 31 set/query yaw centidegrees (`-1` = query), 32 pitch centidegrees,
  - 33 distance per-mille of home, 35 projection (0 persp/1 ortho),
  - 36 immediate first-open reset, 105 capture-clean viewport,
  - 106 force present (returns presented frame count), 107 capability mask (0x7),
  - 108-123 effective source-to-viewer transform, one row-major float per field.
  Do **not** reuse 37/38/39: they fall through to existing texture smoke values.
  The handler guard allows wParam <= 123.
- **Camera convention:** identity = eye on +Z looking at the home centre. T20
  views: front 0/90, oblique 30/60, lens 0/90 at 0.42x, window 18/70 at 0.48x,
  orbit 0/90/180/270 at 75. `pitch 90` is a true horizon front view.
- **Capture contract:** state Ready + generation match + `HasCompleteModel` +
  quiet texture counters + stable non-blank pixels. The viewport crop removes
  toolbar/bottom bar; capture-clean removes gizmo/reset/warning/loading/HUD/
  info/flyout/tooltip overlays. The harness never moves the mouse.
- **Load-time gotcha:** Car reported complete (~4.8 s) while the viewport stayed
  background-only until ~14-15 s. Texture counters were already stable. The lane
  waits for visible pixels; this remains a T23 complete-load readiness defect.
- **F3D:** installed 3.5.0 / VTK `9.6.1-1336-gdc285c2254`. Shipped preset
  `C:/Program Files/F3D/share/f3d/configs/config.d/05_all.json`; controlled run
  uses `--no-config --up +Z --camera-view-angle 45`. Preset renders at 1920x1350
  for a 1280x900 request (DPI-aware); controlled at 1280x900. Never compare them
  as matched.
- **F3D source:** `D:/repos/github/f3d` at `7f32e1f3e02fecbcc0cc2ba74a97bcb18cc28e58`,
  declaring 4.0.0. No local 4.0.0 binary; do not attribute 3.5.0 images to it.
- **Khronos glass:** route documented in the README/report; no sample viewer
  installed, so it is `incomplete`. F3D gray Camera lens is a known defect.
- **Run time:** ~5 min including build, 53 captures, 4 F3D renders, microscope
  and Car first-draw waits. Keep worker suites serial; this lane launches the
  viewer only.
- **No-corpus proof:** calling `capture_cases` with a synthetic unavailable
  inventory produced 18/18 generated captures with no failures and external
  qualification `incomplete`.
- **Performance on this workstation (not a reference-hardware claim):**
  RTX 4080, driver 32.0.16.1714. Default-case load seconds: Camera 8.4, Car 18.1,
  microscope 6.8, base.stl 2.8, generated sphere grid 5.5. Accounted GPU bytes
  ~37-170 MB; viewer private bytes ~650-792 MB. Frame mean ~10-15 ms in these
  captures; the app's mean/p95 fields are not a formal benchmark.

## Flakes / gotchas

- Do not run two viewers at once; the single-instance activation path can steal
  the window. Check `Get-Process Preview3D` if a run cannot find its window.
- `PrintWindow` and screen capture both showed the same delayed first drawable
  frame; the fix was waiting for visible pixels, not changing capture method.
- Accepted references store camera + physical viewport. Changing a profile view
  invalidates them; promote deliberately after review.
