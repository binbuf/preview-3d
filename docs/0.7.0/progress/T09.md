# T09 — OCCT host: XBF and FCStd

## Reusable facts

- **Wire identities:** `SourceFormatId::Xbf = 16`, `Fcstd = 17` (appended).
  Catalog `FormatId::Xbf = 17`, `Fcstd = 18`; both use
  `ImporterKind::CadHost`, `ThumbnailFamily::None`, and the existing
  `Preview3DStepHost.exe` route. `CadFormat::Xbf = 3`, `Fcstd = 4` extend the
  closed discriminator and `ParseCadFileRequest` (56 bytes, unchanged).
- **Broker:** `ImportFormat::Xbf`/`Fcstd` are CAD-only, producer
  `ImportProducer::StepHost`, opcode 22. They are added to the expected-format
  checks, Tier-B classification, and producer/format pairing in both
  `ImportSession.cpp` and `SharedSectionValidator.cpp`.
- **XBF admission:** `compatibility-host-step/src/CadPreflight.{h,cpp}`,
  `XbfPreflightBytes`/`XbfPreflightHandle`. Requires the 7-byte `BINFILE`
  magic plus little-endian 64-bit `0x0000000704030201`; byte cap reuses the
  2 GiB CAD source limit. A file truncated after a valid header passes
  admission and fails later in OCCT with `MalformedData`.
- **XBF reader:** `StepXdeAdapter.cpp` opens a `TDocStd_Application` with
  `BinXCAFDrivers::DefineFormat` and `app->Open(stream, doc)`. The result is an
  XCAF document, so colors/assembly/placements reuse the existing planner.
  `GetLengthUnit` provides the positive metre factor; absence becomes `0.001`
  plus `kCadFeatureXbfUnitAssumedMillimetre` (3013). Up axis is `Unknown`.
- **FCStd admission:** `FcstdPreflight.{h,cpp}`. ZIP EOCD/central/local
  reconciliation (including ZIP64), one disk, no encryption (flag 1/0x40), no
  data descriptors (flag 0x8), stored/Deflate only, safe/unique names,
  non-overlapping entry ranges. Limits: 2 GiB source, 4096 entries, 256 MiB
  per entry, 512 MiB aggregate, 200:1 expansion. Requires `Document.xml` and
  at least one `*.brp`.
- **FCStd XML/reader:** `FcstdReader.{h,cpp}`. Bounded XML parser rejects
  DOCTYPE/ENTITY and enforces 8 MiB / 200,000 nodes / depth 64. Shape file
  attributes must be safe package-relative paths and must exist in the
  package. Supported subset: evaluated Part/PartDesign `*.brp` shapes,
  `ShapeColor`, `Transparency`, visibility (Document + Gui fallback), local
  links, link arrays, nested `App::Part`/`Assembly` placements, and
  `DiffuseColor.bin` face colors. External links and unknown objects are
  skipped with bounded warnings (`3015`/`3016`); all other FreeCAD objects and
  features are not evaluated.
- **FCStd units:** millimetres by FreeCAD convention. Reader adds
  `kCadFeatureFcstdMillimetresAssumed` (3014), wire reports `0.001` and
  `UpAxisId::Unknown`. `SceneMetadataRules.h` requires `Unknown` + a positive
  metre factor for both (the adapter reports `0.001` for FCStd); an unknown-up
  or zero-unit section is rejected.
- **Compatibility IDs:** 3013 XBF unit assumed mm, 3014 FCStd millimetres,
  3015 FCStd external link ignored, 3016 FCStd unsupported object. Host text
  added in `interactive-viewer/src/app/CompatibilityText.h`.
- **Catalog/installer:** `ProgIdForFamily` adds `Binbuf.Preview3D.XBF.1` and
  `Binbuf.Preview3D.FCStd.1`; `Preview3D.nsi` registers/unregisters `.xbf`
  and `.fcstd`. Open-dialog/Open As lists remain catalog-driven.
- **Fixtures:** `tests/fixtures/cad-spike/`.
  - `assembly.xbf`: generated by the extended `GenerateCadFixtures.cpp`
    (box placed twice + colored cylinder, document unit 0.001).
  - `truncated.xbf` (cut after a valid header) and `malformed.xbf`
    (unsupported binary-document version).
  - `partdesign.FCStd`, `external_link.FCStd`, `malformed.FCStd`,
    `nodocument.FCStd`, `truncated.FCStd`, `zipbomb.FCStd`,
    `oversized.FCStd`: generated by `GenerateFcstdFixtures.py` from the local
    `part.brep`. All fixtures are generated from repository-owned primitives
    or the repository's own BREP; no third-party model license applies.
- **Tests:** `tests/import-isolation/CadHostTests.cpp`
  (`[cad-xbf]`, `[cad-fcstd]`, `[cad-validator]`). Positive scenes assert
  typed result, format/axis/unit, geometry/material/instance counts and
  bounds; negative cases cover truncated XBF, truncated/malformed/missing
  document/zip-bomb/oversized FCStd and cross-format reads. Validator cases
  pin the XBF/FCStd metadata rules.

## Gotchas

- `std::deque<XmlNode>` inside `XmlNode` is not a complete type for MSVC;
  the XML tree uses `std::vector<std::unique_ptr<XmlNode>>` so an open child
  address stays stable while siblings append.
- `TDocStd_Application::Open(stream, doc)` returns `PCDM_ReaderStatus`; XBF
  needs `BinXCAFDrivers::DefineFormat` first. Close the opened document through
  the same application, not always the XCAF singleton.
- FCStd preflight rejects data descriptors (flag 0x8). Python `zipfile` writes
  seekable archives without them; streaming archive writers may legitimately
  produce them and are intentionally unsupported.
- The ZIP scanner checks `EntryTooLarge` from the central directory before
  reading any local data, so `oversized.FCStd` stays 124 bytes.
- The StepHost manifest now includes `zlib`, but `VcpkgManifestInstall` remains
  false. The current workspace copied `zlib.h`/`zconf.h` and `zs.lib` from the
  root vcpkg tree into
  `compatibility-host-step/vcpkg_installed/x64-windows-static-md`. A clean
  restore should produce them from the manifest.
- Do not add a face-color fallback that overrides a valid shape color for a
  `DiffuseColor` list of length 1; the reader promotes one-entry lists to the
  object color.
- `assembly.xbf` and the regenerated T08 fixtures carry OCCT creation
  timestamps; regenerating does not reproduce bytes exactly.
