## What landed

- **Fitted map.** `viewer_ground_shadow::FitShadowFrustum` in
  `interactive-viewer/src/render/GroundShadow.{h,cpp}` builds a square
  orthographic light frustum from verified world bounds and the active world
  light, snaps the centre to whole texels, clamps grazing light, and derives a
  scale-invariant normalized depth bias. `ShadowMatrixForCameraTarget` converts
  it to consume camera-relative positions.
- **Caster pass.** `D3D12ViewerPath::CreateShadowPipelines` owns a depth-only
  `D32_FLOAT` pass plus an `R8_UNORM` attenuation target. It uses
  `kShadowOpaqueVertexShaderSource` (POSITION only) for opaque/transmissive
  meshes and `kShadowMaskPixelShaderSource` (POSITION+TEXCOORD0, base-colour
  alpha discard) for MASK cutouts. Cull is off; BLEND surfaces are excluded;
  transmissive surfaces write `clamp(1 - 0.60*transmission, 0.40, 1)`.
- **Ground layer.** `kShadowGroundPixelShaderSource` samples the fitted map
  with a comparison sampler and 3x3 PCF, subtracts the fitted bias, samples the
  caster attenuation, and writes premultiplied black coverage into the linear
  HDR target. The display-space Ground highlight remains the ADR-0079 layer.
- **Lifecycle.** `ShadowResources` owns the depth/mask targets, heaps and
  byte counts. They are created once per device, are not viewport-sized
  (resize keeps the same allocation), are released/recreated in `Initialize`
  for device recovery, and are included in `AccountedAllocationBytes`.
  Allocation failure or the Debug force switch falls back to the labelled
  analytic bounds ellipse; point/line-only content gets no ellipse.
- **Diagnostics.** Debug fields 279 mode, 280 fallback reason, 281/282 target
  bytes, 283 caster count, 284 map extent, 285 caster-pass microseconds,
  286 query/force fallback. The Debug guard now allows `wParam <= 286`.
- **Fixture/lane.** `contact-shadow-probe` in `fixtures.py` (suspended ring,
  two tyre-like contacts, suspended sphere, equal opaque/clear panels, MASK
  cutout sheet, mirrored part). `tests/render-quality/contact_shadows.py`,
  `profiles/T31.json`, `verify.py` route T31 after T29 and include T31 in the
  unit-test build tuple. `tests/render-quality/review/T31-review.json` records
  the reviewed images and honest limitations.

## Reusable facts / gotchas

- **D3D12 PSO input signatures must match the VS.** The first caster PSO used
  one VS declaring POSITION+TEXCOORD0 with a POSITION-only input layout and
  `CreateGraphicsPipelineState` returned `E_INVALIDARG`; startup then failed
  with the default import error (code 4, stage 1), which looked like an importer
  fault. Keep separate VS blobs for the opaque (POSITION only) and MASK
  (POSITION+TEXCOORD0) casters.
- **Resource initial state.** Create the depth/mask targets in
  `PIXEL_SHADER_RESOURCE` so every frame runs the same
  resource→depth/render-target→resource transition cycle.
- **Camera-relative matrix.** Do not feed world-space positions to the ground
  shader; use `ShadowMatrixForCameraTarget` so the ground quad's
  camera-relative position maps to the same light clip as the world caster.
- **Sparse content.** `viewer.set_camera` calls `wait_stable`, whose non-blank
  heuristic rejects the line/point fixture. Use the first-open framing and
  `capture()` rather than a forced camera for line/point-only checks.
- **External reload cost.** Reopening Car after a long generated/readback
  session can fail to settle even at 240 s. Run the external survey in a fresh
  `Viewer` process (the lane now does).
- **Shadow pair state.** Read the shadow diagnostics immediately after the
  shadow-on capture; `_shadow_pair` turns the shadow off for the off image.
- **Fallback is broad.** The analytic ellipse covers roughly a quarter of the
  viewport on the contact fixture; that is why it is fallback-only and must not
  be called the shipping shadow.
