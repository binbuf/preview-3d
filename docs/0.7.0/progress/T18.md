# T18 - Material lobes and transparency

## Reusable facts

- **Wire version is 12** (`model_core::kCurrentProtocolVersion == 12`). v11 and
  every earlier section is rejected outright. `MaterialPayload` is now 140 bytes
  (`shared/model-core/include/model_core/MaterialPayload.h`); the v12 block is:
  `emissiveStrength` @72, clearcoat factor/roughness @76/80, `sheenColor[3]` @84,
  `sheenRoughness` @96, `specularFactor` @100, `specularColor[3]` @104,
  `ior` @116, `occlusionStrength` @120, `reserved[4]` @124. Reserved words must
  be exactly zero.
- Value-initialized `MaterialPayload{}` now supplies the pre-v12 defaults
  (emissive 1, no coat/sheen, specular 1/white, IOR 1.5, AO strength 1, zero
  reserved), so zero-initializing producers required no per-field edits.
- Shared helpers in `MaterialPayload.h`: `IorToF0`, `MaterialDielectricF0`,
  `SheenLobeWeight`, `ClearcoatBaseSpecularScale` and
  `ValidateMaterialLobeFields`. The validator calls the last one; unit tests
  exercise the same function.
- **glTF mapping** in `import-worker/src/GltfAdapter.cpp` `ResolveMaterial`:
  clearcoat/sheen/specular/IOR/emissive-strength/occlusion strength. T05 policy
  rows for `KHR_materials_clearcoat`, `sheen`, `specular` and
  `emissive_strength` are now `adapterSupported=true`; iridescence, anisotropy,
  volume, dispersion and diffuse_transmission stay false and still emit specific
  Degraded records. Texture-driven lobe maps emit a bounded texture warning
  (the fixed payload has no extra slots).
- **FBX/OBJ** share `UfbxMaterialConversion.cpp`; ufbx PBR coat/sheen/specular/
  IOR/AO values are mapped, and the old coat/sheen feature warning was removed.
- **Shader** (`interactive-viewer/src/app/D3D12ViewerPath.cpp`): material root
  constants grew 20 -> 36 dwords. `gMaterialLobes0..3` carry
  {emissive strength, clearcoat factor, clearcoat roughness, occlusion strength},
  {sheen rgb, roughness}, {specular factor, IOR, 0,0}, {specular color rgb,0}.
  Clearcoat is a second dielectric GGX lobe; base specular is multiplied by
  `(1-clearcoatFactor)`. Sheen is `pow(1-NV,3)` with a roughness weight.
  `IorToF0` + specular factor/color replace the fixed 0.04. Emissive strength is
  applied before the HDR resolve. Clay suppresses all three lobes. Both the
  opaque/material path and the wireframe path upload all 36 dwords.
- **Transparency:** T15's model is unchanged: opaque first, blend draws
  stable-sorted back-to-front, then the resolve applies background/exposure/
  neutral tone curve in linear space. Weighted blended OIT and depth peeling are
  deferred; intersecting transparent surfaces remain order-dependent. The
  transmission approximation remains Fresnel-weighted alpha with suppressed
  transmitted diffuse (using the IOR/specular F0 now).
- Thumbnail path: `CpuRasterizer.cpp` applies emissive strength; provider glTF
  `ToMaterialPayload` records the new fields but the CPU thumbnail lighting does
  not draw clearcoat/sheen (documented provider limitation).
- **Cache identity:** `interactive-viewer/src/cache/DerivedCache.cpp` bumps the
  entry schema from 2 to 3, so a v2 entry carrying the old 72-byte material
  record is a miss rather than a reinterpretation. The cache key's
  `parserVersion` is caller-supplied (still not wired in this tree).

## Gotchas

- Import-isolation sandbox tests must not be run as parallel processes against
  the same worker/sandbox: an intermittent `received.has_value()` failure
  appears when several test executables contend. Re-running the lane alone
  passes.
- `FindGltfCompatibilityChunks` returns a null `status` when a generation has no
  flags/warnings, so supported-lobe tests must assert `report == nullptr` rather
  than require an `ImportStatus` chunk.
- Any remaining test that pins protocol 11 (CadHost/Step/USD/WireFormat) must
  become 12; there is no mixed-version fallback.
- `MaterialPayload` default member initializers are relied on by producers that
  use `MaterialPayload payload{}`; do not replace them with zero-init semantics.

## Follow-ups

- Weighted blended OIT or depth peeling for intersecting transparent surfaces;
  sorted straight-alpha is the shipped limitation.
- Material inspection modes (base color, metallic, roughness, normal, UV
  checker) were not added; only the existing Studio/Clay/Directional/Wireframe
  modes ship.
- Texture-driven clearcoat/sheen/specular maps are warning-only; a later wire
  version would need additional dependency slots.
- Thumbnail CPU rasterizer does not shade clearcoat/sheen; only emissive
  strength is consumed there.
- Anisotropy/iridescence/volume/dispersion remain parse-and-warn; the four
  reserved words are the future extension point behind a new version bump.
- Derived cache `parserVersion` is not populated from
  `kCurrentProtocolVersion` in the current tree; protocol-v12 sections
  invalidate the wire path, but a future cache-wiring change must include the
  version explicitly.
