# T04 - Compatibility severity model and report chunk

## Reusable facts

- Header: `shared/model-core/include/model_core/Compatibility.h`.
  - `CompatibilitySeverity { Critical=0, Degraded=1, Ignored=2 }`.
  - `CompatibilityRecord` is exactly **12 bytes** (packed:
    `featureId u32`, `severity u8`, `reserved[3]`, `count u32`).
  - `CompatibilityReportPayload` is exactly **776 bytes**: `recordCount u32`,
    `reserved u32`, `records[64]`.
  - `kMaxCompatibilityRecords = 64`; `kCompatibilityCountCap = 1'000'000`.
  - `kCompatibilityReportChunkId = 0xf0000003`.
- `ChunkTopology::CompatibilityReport = 10` (WireFormat.h, additive; protocol
  version stays **10**, no layout change).
- Feature-ID ranges (append-only, constexpr helpers `IsKnownFeatureId`):
  glTF 1-999, 3MF 1000-1999, USD 2000-2999, STEP 3000-3999,
  texture 4000-4999, container 5000-5999.
- Named glTF IDs: clearcoat 1, sheen 2, specular 3, iridescence 4,
  anisotropy 5, volume 6, emissive-strength 7, dispersion 8; unknown glTF
  extensions share 900. `GltfExtensionFeatureId(name)` is the pure mapping.
- Producer helper: `CompatibilityReportBuilder::Add(id, severity, count=1)`
  dedups by `(featureId, severity)`, saturates count, rejects unknown IDs /
  zero count / bad severity / more than 64 distinct records.
  `BoundedChunkWriter::AddCompatibilityReport(builder)` emits the fixed-id
  chunk (no-op when empty).
- glTF adapter still increments `optionalFeatureWarnings` exactly as before,
  and now also emits a `Degraded` record per unsupported `extensionsUsed`
  entry, in both the streaming and single-section paths.
- Validator (`SharedSectionValidator.cpp`): exact payload size, fixed chunk
  ID, at most one per generation (also enforced in `ImportSession`), zero
  dependencies/reserved bytes/padding, severity <= Ignored, known feature ID,
  count in `[1, kCompatibilityCountCap]`.
- Host: `ImportResult::compatibility` and `ModelData::compatibility` hold
  `std::vector<CompatibilityRecord>`; `RenderThread.cpp` merges per batch
  (same dedup/saturation) and `CompatibilityWarningText` composes up to four
  specific localized messages, falling back to the old generic text only when
  no record maps to host text.
- Host text table: `interactive-viewer/src/app/CompatibilityText.h`
  (`CompatibilityFeatureText`, `CompatibilitySeverityLabel`,
  `CompatibilityWarningText`). Never accept worker text.
- Diagnostics (`D3D12ImportBridge.cpp::DiagnosticDetails`) append
  `Compatibility: feature <id> (<severity>) x<count>`, no source path.
- Hostile-worker modes: `--compat-count`, `--compat-size`,
  `--compat-severity`, `--compat-reserved`, `--compat-feature`,
  `--compat-padding`, `--compat-dependency` (`RunCompatibilityAttack`).
- Docs: `docs/design/03-file-formats-and-ingestion.md` (Wire format ->
  "Compatibility report chunk"); ADR
  `0059-compatibility-feature-ids-and-report-chunk.md`.

## Gotchas

- The record's named fields sum to 12 bytes, not 11; the static_assert and
  docs were corrected after the first compile. Keep the payload at 776.
- `CompatibilityReportPayload` is written with `std::as_bytes(std::span(&p,1))`
  from a packed struct; all unused record slots must stay zero because the
  validator rejects nonzero padding.
- `RenderThread` gets status/report chunks through per-batch publications, so
  both the terminal and non-terminal branches must merge the records before
  `RebuildModelWarning`.
- Preview3D's STEP generic-warning override still replaces the banner whenever
  `optionalFeatureWarnings` is set for STEP. STEP does not emit compatibility
  records yet, but T07 must not rely on the generic path after it adds records.

## Follow-ups

- T05: refine glTF severities (required-but-approximated vs ignored), map any
  newly supported extension IDs, and consider more named IDs instead of the
  generic 900 bucket.
- T07/T10b/T11: add STEP/3MF/USD named IDs inside 3000/1000/2000 ranges and
  host localization entries; do not renumber.
- T12/T13: reserve texture IDs in 4000-4999 and container IDs in 5000-5999.
- Consider appending host text for other glTF extension IDs (unlit, variants,
  lights) when their adapters start reporting records.
