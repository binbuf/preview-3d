# T08 — OCCT host: IGES and BREP

## Reusable facts

- **Wire identities:** `SourceFormatId::Iges = 14`, `Brep = 15` (appended).
  Catalog `FormatId::Iges = 15`, `Brep = 16`; `ImporterKind::CadHost` is now a
  shipped importer. Both use `ThumbnailFamily::None` so the STEP-only provider
  closure is not asked to open them.
- **Host route:** STEP keeps opcode 20 / `ParseStepFileRequest` (48 bytes).
  IGES/BREP use opcode 22 `StartCadImportFromFile` / `ParseCadFileRequest`
  (56 bytes: the seven STEP fields plus `uint32_t cadFormat`, `uint32_t
  reserved0`). `CadFormat { Step=0, Iges=1, Brep=2 }`; the host validates it
  before preflight. Both formats still use `ImportProducer::StepHost` and
  `Preview3DStepHost.exe` under `StepHost\`.
- **Quality:** all CAD formats reuse the T07 STEP quality bits and tessellation
  profile. No new flag bits were needed.
- **IGES admission:** `compatibility-host-step/src/CadPreflight.{h,cpp}`.
  80-column S/G/D/P/T records, strictly increasing sequence per section, section
  order S→G→D→P→T, byte cap 2 GiB, 5M records, 5M D entities, 100M parameter
  tokens, no control bytes/truncation. Global parameter 14 is extracted as the
  unit flag (bounded Hollerith-aware tokenizer).
- **BREP admission:** same file. Accepts an optional `DBRep_DrawableShape` line
  then `CASCADE Topology V1/V2/V3`; scans `Locations <n>` and `TShapes <n>`
  (2M shapes / 1M locations), line cap 5M, byte cap 2 GiB, rejects control
  bytes, `Interrupted by the user`, and a non-empty shape table with no records.
- **IGES reader:** OCCT's IGES work library has no `ReadStream`
  (`IFSelect_WorkLibrary::ReadStream` returns failure), so
  `IGESControl_Reader::ReadStream` always fails even for valid bytes. T08 adds
  `IgesStreamReader.{h,cpp}`: it feeds the admitted records to the pinned C
  parser symbols in `TKDEIGES` (`iges_initfile`, `iges_param`, `iges_Dsect`,
  `iges_Psect`, `iges_stats`, `iges_lirparam`, `iges_lirpart`, etc.), builds
  `IGESData_IGESReaderData`/`IGESData_IGESModel`, and installs it on the
  `IGESCAFControl_Reader` session. No temp file or path is created.
- **BREP reader:** `BRepTools::Read(shape, stream, BRep_Builder)` from the
  mapped stream, then `XCAFDoc_ShapeTool::AddShape`. No XDE colors/units.
- **Units:** IGES reports `0.001` (verified OCCT system millimetre after the
  actor's unit conversion); an absent/zero global unit flag adds compatibility
  feature 3010, a declared non-mm unit adds 3011. BREP reports `0.0` and adds
  ignored feature 3012 (no authored unit; never guessed). Up axis is `Unknown`
  for both. `SceneMetadataRules.h` enforces Iges `Unknown && >0` and Brep
  `Unknown && ==0`.
- **OCCT closure:** `packaging/vcpkg-ports/opencascade/portfile.cmake` now keeps
  `TKDEIGES` in the DataExchange module list (port-version 2). The installed
  closure is gitignored; for this workspace `TKDEIGES.lib` was built
  incrementally in the existing vcpkg blds dirs and copied to
  `compatibility-host-step/vcpkg_installed/x64-windows-static-md/{lib,debug/lib}`.
  IGES headers were copied from the OCCT source toolkits because the installed
  include tree predated the port change. A clean restore should produce them
  automatically.
- **Fixtures:** `tests/fixtures/cad-spike/`. `GenerateCadFixtures.cpp` writes
  `part.igs` (box+hole, green), `assembly.igs` (shared box twice + coloured
  cylinder), `part.brep`, `compound.brep`, `truncated.igs`, `malformed.brep`.
  All generated from OCCT primitives in the generator; no third-party model
  license applies. Generator build command (developer tool, not in the
  solution):
  - `cl /std:c++20 /EHsc /MD /O2 /DNDEBUG /permissive- /utf-8 /I<occt include>
    tests\fixtures\cad-spike\GenerateCadFixtures.cpp /Fe:GenerateCadFixtures.exe
    /link /LIBPATH:<occt lib> TK*.lib user32.lib ...` under `vcvars64`.
- **Tests:** `tests/import-isolation/CadHostTests.cpp` (`[cad-iges]`,
  `[cad-brep]`, `[cad-validator]`, `[cad-iges][protocol]`). Positive scenes
  assert format/axis/unit, verified bounds, triangle counts, IGES materials and
  X-extent spanning occurrence transforms. Negative cases cover truncated IGES,
  malformed BREP, over-budget preflight limits, and cross-format opcode/file
  mismatches.
- **Catalog/installer:** `ProgIdForFamily` adds `Binbuf.Preview3D.IGES.1` and
  `Binbuf.Preview3D.BREP.1`; `Preview3D.nsi` registers/unregisters `.igs`,
  `.iges`, `.brep`. `FormatRegistrationTests` still enforces catalog/installer
  drift. `--format iges`/`brep` now parse.

## Gotchas

- Do not use `IGESControl_Reader::ReadStream`; it is a base-class no-op for
  IGES. Use `ReadIgesModelFromStream` and `WS()->SetModel` +
  `InitTransferReader(4)`.
- OCCT's `BRepTools::Write` writes `DBRep_DrawableShape` before the versioned
  header; admission must allow exactly that optional prefix or every real BREP
  file is rejected.
- `BRepTools::Read`/`TopTools_ShapeSet::Read` print errors with `std::cout`;
  the host's stdout is the binary control channel. The CAD adapter wraps
  IGES/BREP reads in `ScopedCoutSilencer` so kernel text cannot corrupt the
  channel.
- IGES `UnitValue()` is in Cascade units, not metres; the stored geometry is
  normalized to the system millimetre, so the scene factor is `0.001`, not the
  authored unit value.
- BREP has no unit: `0.0` is required by the validator. Do not "improve" it to
  0.001 or the hostile-section tests and the unspecified-units contract break.
- `tests/fixtures/cad-spike/*.exe/.lib/.exp` are build artifacts; regenerate
  from source and do not commit them.
- The port-version bump matters: without it vcpkg may reuse an archive built
  from the old module list.
