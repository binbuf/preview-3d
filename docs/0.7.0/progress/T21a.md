# T21a - Windows Photos-style background and ground highlight

## Reusable facts

- **Gate:** `python tests/render-quality/verify.py --task T21a --configuration Debug --output TestResults/render-quality/T21a`.
  It builds `Preview3D` Debug, runs the T20 capture-contract self-tests, captures
  the generated `sphere-grid` default/front cases, then runs
  `tests/render-quality/appearance.py` against real GPU pixels. Exit 1 on any
  failure. The 2026-10-30 run passed (24 appearance checks, 8 highlight/shadow/
  grid combinations, Car + Camera external evidence).
- **Profile:** `tests/render-quality/profiles/T21a.json`. Unknown/empty profiles
  and missing images still fail through the existing T20 runner contracts.
- **Debug appearance fields** (WM_APP+104, `--app-smoke` only, guard `<= 200`):
  - 93 query / 94 set background mode (0 dark, 1 gray, 2 transparent,
    3 checkerboard, 4 custom);
  - 195 query / 196 set the ground-highlight switch;
  - 197 query / 198 set packed custom color `0xRRGGBB`;
  - 199 flushes the same persisted state the Settings UI writes.
  - Existing 67 (Debug DPI 96/144/192) and 68 (high contrast) are reused for
    Settings images. 101/102 remain shadow query/set; 103/104 grid.
- **Evidence:** `TestResults/render-quality/T21a/appearance/appearance.json`,
  `appearance/images/*.png`, plus the normal `report.json`/`captures.json`.
  Review record: `tests/render-quality/review/T21a-review.json`.
- **Colour contract:** the backdrop is a separate `R8G8B8A8_UNORM` display
  target. `#1C1C1E` reaches the PNG as 28/28/30; studio gray arrives as
  127/127/127 (UNORM 0.5 quantizes to 127); custom `#336699` arrives exactly.
  Tolerance is 3 channel units. It does not move with exposure or tone map.
- **Compositing:** the resolve recovers straight-alpha scene colour, tone-maps
  it, then `lerp(backdrop, mapped, coverage)`. Transparent captures emit
  premultiplied display colour with preserved alpha; checkerboard is display
  space. CPU reference: `viewer_presentation::CompositeOverBackground`.
- **Ground treatment:** drawn into the display backdrop as premultiplied
  source-over. Highlight is backdrop + 0.055 with a radial fade and peak alpha
  0.55; shadow opacity 0.78/softness 0.50. `parameters[2]` gates the highlight
  and `parameters[3]` gates the shadow, so either can be off while the other
  remains visible.
- **Persistence:** settings version 8 adds `backgroundColor` and
  `groundHighlightEnabled`. Background mode 4 is appended; values 0-3 keep
  their old meanings. The appearance harness backs up/restores the developer's
  real `%LOCALAPPDATA%\Binbuf\Preview 3D\settings.json`.
- **Gotcha:** Debug field 195 is a query, 196 sets. Do not query a setter field
  (e.g. 102/104) with value 0: it changes state. Use 101/103 for shadow/grid.
- **Gotcha:** the first `PrintWindow` capture after launch can be the white
  pre-first-frame surface; `appearance.py::_settle` waits until the corner is
  no longer near-white. Do not run two viewers at once.

## Verified behavior

- Backdrop corners match #1C1C1E / #808080 / #336699 before and after model
  load, across exposure 0.3/1.0/2.5 and Neutral/ACES/Filmic (max delta 0-1).
- All eight highlight x shadow x grid combinations capture and query the
  requested independent state. Highlight off still shows the contact shadow
  (ground delta 2.94); with the highlight on, the shadow toggle still changes
  the ground (2.46). Highlight on vs off changes the ground (8.00) but not a
  sampled model interior (0.0002; the probe box is fully inside the white
  sphere, not a gap between spheres).
- Background/custom/highlight survive restart and model open, all three
  lighting modes, and a manual Transparent preset. Malformed values fall back
  to dark/highlight-on while an unrelated setting is preserved.
- Settings panel rows reflow at 100/150/200% Debug DPI, narrow window and high
  contrast; Tab traversal runs without an exception.
- Car windows and Camera lens show unchanged materials and no new halos on
  dark/gray/custom backdrops.
