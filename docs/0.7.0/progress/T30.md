## What landed

- **World sun contract.** `interactive-viewer/src/render/LightRig.h` owns the
  documented Z-up convention and `DirectionalSunDirection`. Azimuth is
  normalized 0..1 around +Z (0 = +X, 0.25 = +Y, 0.5 = -X, 0.75 = -Y);
  elevation is radians clamped to `kMaxSunElevation = 1.4835`.
- **One consumer chain.** `gSunDirection` (new frame constant) drives the
  material and legacy compact shaders; `NavGizmo::ComputeSun` and
  `GroundShadow::ProjectShadow` call the same helper. Directional shadows use
  the sun; Studio keeps `(0.45, -0.55, 0.70)`.
- **Correct frame.** The vertex path subtracts the camera origin but leaves
  directions in world axes; the view matrix applies the camera rotation. The
  material shader therefore uses the world sun directly. The old
  camera-space az/el branch and the extra camera rotation are gone.
- **Coat/environment cleanup.** Directional base and coat use the same
  `lightDir`; no Studio key remains in the Directional branch or legacy shader.
  Sheen scales with environment intensity instead of the old flat 0.35 lift.
- **Debug state.** Fields 277/278 read/write sun azimuth/elevation as IEEE
  float bits (`lParam == -1` reads); the guard now allows wParam <= 278.

## Reusable facts

- **Shader frame gotcha.** `BuildCameraRelativeInstanceTransform` subtracts the
  camera origin but does **not** rotate by the camera. `worldPosition`,
  shading normals and `viewDir` are in the fixed Z-up world frame; camera
  rotation lives in `gViewProjection`. Do not apply `gWorldFromCamera` to the
  Directional sun. `RotateWorldFromCamera` remains the existing IBL frame
  conversion, not direct lighting.
- **glTF up-axis gotcha.** Generated glTF fixtures are authored Y-up. The
  import correction maps source `(x,y,z)` to world `(x,-z,y)`. In the T30
  fixture the world wall (XZ plane, normal -Y) is authored as a source XY plane
  with normal +Z; the world floor at z=-1 is a source XZ plane at y=-1 with
  normal +Y. Mis-authoring this makes the wall edge-on.
- **Locator gotcha.** `material_semantics._locate_probes` classifies pixels by
  tone-mapped base colour with a 70×70 RGB distance. Avoid base colours close
  to the #1C1C1E backdrop or to each other; otherwise the background wins and
  the centroid is meaningless. The T30 fixture uses a dark maroon black paint
  (0.16,0.04,0.08) and a magenta emission base (0.55,0.08,0.48) for this reason.
- **Sampling gotcha.** Flat panels are uniform; sample one interior pixel
  (`sample_region(x,y,x+1,y+1)`) rather than an 8×8 block. A foreshortened edge
  can otherwise mix backdrop alpha and make a 12.5 % direct-response drop look
  like sun motion.
- **Debug `<cmath>`.** `Preview3D.cpp` now includes `<cmath>` explicitly for
  `std::isfinite`/`std::floor` used by fields 277/278.
- **Lane files.** `tests/render-quality/directional.py`,
  `profiles/T30.json`, fixture id `directional-probe` in `fixtures.py`,
  `EXPECTED_MATERIALS['directional-probe']`. `verify.py` imports `directional`
  and routes T30 after T29; T30 is in the unit-test build tuple.
- **Fixtures.** `directional-probe` is six wall panels (lambert, coat, black
  paint, gold metal, thin glass, emission) plus a horizontal floor Lambert
  panel. The lane disables grid/shadow/highlight (fields 104/102/196 = 0).
- **Exposure band.** At the fixed front camera, Studio mean luma is 32.0 and
  Directional is 35.1 (ratio 1.095). This is a sanity band, not image equality.
- **Perf.** No new GPU target/pass/allocation. The CPU sun helper adds a few
  trig operations per frame.
