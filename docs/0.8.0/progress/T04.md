# T04 — Assimp point and line primitives

## What landed

- `import-worker/src/AssimpAdapter.cpp` now emits one chunk per topology:
  one-index faces become `PointList` (no index buffer), two-index faces become
  `LineList` segments, and three-or-larger faces become `TriangleList`
  (fan-triangulated only as the fallback after `aiProcess_Triangulate`).
- A mixed source mesh emits deterministic triangles → lines → points chunks,
  each carrying the mesh material dependency and the existing
  `PositionNormalUv0TangentColor_F32` attributes.
- `WalkNode` no longer requires `aiPrimitiveType_TRIANGLE`; a mesh with no
  supported face is skipped with the bounded optional-warning count.
- The final `EmptyGeometry` check uses `totalPrimitives` (triangles + segments
  + points) instead of triangles only.
- Per-topology chunk limits use `kChunkTriangles` (triangles/lines) and
  `kChunkPoints` (points), computed from the same output window; emitted
  primitives and vertices still count against `maxTriangles`/`maxVertices`.
- Degenerate segments and non-finite points/line endpoints are skipped with a
  bounded warning. `OffAdmission` accepts one/two-index faces.
- Assimp's synthetic skeleton "hero" mesh is disabled with
  `AI_CONFIG_IMPORT_NO_SKELETON_MESHES`, so an empty COLLADA document fails
  typed instead of presenting fabricated triangles.
- New generated fixtures under `tests/fixtures/assimp-spike/`: `lines.dxf`,
  `lines.off`, `lines.dae`, `lines.x3d`, `points.off`, `points.x3d`,
  `mixed.x3d`, `degenerate-lines.off`, `non-finite-points.off`, `empty.dae`,
  `over-budget-lines.off`, `over-budget-points.off`.
- `[assimp-primitives]` coverage in
  `tests/import-isolation/AssimpImportTests.cpp` (7 cases / 79 assertions):
  line-only DXF/OFF/DAE/X3D, point-only OFF/X3D, mixed point/line/triangle,
  degenerate segment warning, non-finite point warning, empty/malformed typed
  failure, and line/point over-budget rejection.
- Valid-file scoreboard flipped for `line-dxf-polyline`, `line-off-edges`,
  `line-dae-lines`, `line-x3d-indexedlineset` (opened/lines) and
  `points-x3d-pointset` (opened/points). `points-dae-points` is now
  failed/`EmptyGeometry`/primitive because Assimp has no COLLADA point
  primitive. `line.off` was regenerated as a valid three-edge OFF.
- Docs: `docs/FORMAT-SUPPORT.md`,
  `docs/design/03-file-formats-and-ingestion.md`, ADR-0098, an amended
  ADR-0065 status/primitive note, and both fixture READMEs.

- Fixture generators are deterministic; run them from the repo root:
  `python tests/fixtures/assimp-spike/generate_fixtures.py` and
  `python tests/fixtures/valid-file/generate_fixtures.py`. The valid-file
  generator rewrites `wire.FCStd` with a fresh ZIP timestamp; revert that file
  if the task did not intend a fixture change.
- `tests/fixtures/valid-file/points.dae` is a valid COLLADA `<points>` file
  that Assimp cannot represent. It is intentionally a typed
  `EmptyGeometry` failure; do not "fix" it with a skeleton mesh.
- Assimp's `aiProcess_SortByPType` usually splits mixed meshes before the
  adapter sees them. The adapter still handles unsplit mixed faces; keep the
  face-by-index-count classification if the flag set changes.
- `PointList` chunks must have `indexCount == 0`; `LineList` chunks must have
  an even index count. The shared validator enforces both, and the viewer
  accepts `PositionNormalUv0TangentColor_F32` for both.
- A finite source double such as `1e300` overflows to infinity when Assimp
  stores it as a float; `Finite()` skips the point/segment with a warning.
- `GenVertexNormalsProcess` writes NaN normals for faces with fewer than three
  indices in a mixed mesh. The adapter uses the position as the usability test
  and falls back to a neutral normal for lines/points instead of dropping the
  primitive.

## Follow-ups

- Point-only DAE remains a typed `EmptyGeometry` failure because Assimp's
  COLLADA importer has no `<points>` primitive. A native COLLADA path or a
  provider-local bounded conversion would be needed; it is not a T04 defect.
- T05 owns CAD edge/wire geometry; keep the `LineList` contract unchanged.
- T08 (compatibility readers/fallback) must not treat the new line/point
  successes as a fallback trigger; they are ordinary opened outcomes.
- T09/T10: the valid-file report now records `lines`/`points` for the flipped
  entries; keep the support matrix and qualification evidence in sync, and
  document the COLLADA `<points>` limitation.
- The viewer already draws line chunks with the neutral line PSO and point
  chunks with the splat pipeline; no new PSO was needed. A future visual
  regression fixture can assert both kinds are visible, but the import gate
  already proves the normalized chunks and bounds.
