# T03 — Catalog-driven content sniffer

## What landed

- `SniffHead` now iterates `model_core::Formats()` and evaluates every
  descriptor's non-ZIP `MagicSignature` entries. Selection is confidence first
  (strong structural over weak textual), then descriptor `priority`; a
  recognized GLB envelope vetoes weaker fallbacks. The catalog stays data-only.
- New `MagicKind`s: `GlbHeader`, `ThreeDsChunk`,
  `XmlPrefixCaseInsensitive` (DAE/AMF/X3D after BOM/XML declaration/comments),
  `DxfSection` (first four non-empty lines), `OffHeader`, `IgesRecord`
  (80-column S/G/D/P/T), `BrepHeader` (`CASCADE Topology V1-V3` or
  `DBRep_DrawableShape`), `XbfHeader` (`BINFILE` + little-endian
  `0x0000000704030201`), and `ZipEntryEqualsAndSuffix` (FCStd `Document.xml`
  plus a `*.brp` entry). `MagicSignature` gained a trailing `aux` token for
  the conjunction kind.
- `ProbeZipCentralDirectory` evaluates catalog ZIP signatures instead of
  hardcoding 3MF/USDZ. The 1 MiB / 8,192-entry / EOCD bounds and ZIP64/spanned
  rejection are unchanged. `SniffHead` still returns Unknown for a ZIP local
  header.
- `AsciiStl`, `AsciiPly`, and the generic `.usd` descriptor now have empty
  signature spans (wire-only variants / extension identity). Every remaining
  descriptor with a signature is reachable by the table-driven probe.
- `[format-sniffer]` coverage: positive + negative for every catalog signature,
  a reachability assertion per descriptor, BOM/whitespace/XML-comment variants,
  truncated/malformed negatives, generic-ZIP/ZIP64/spanned negatives, renamed
  content-only + `DecideOpenFormat` AskUser for DAE/DXF/OFF/X3D/3DS/IGES/BREP/
  XBF/FCStd, a cross-family mismatch prompt, priority checks, and real-fixture
  detection.
- `tests/compat/valid-file-manifest.json`: `renamed-dae-xml` and
  `renamed-dxf-txt` now report `failureClass=extension` (content detected,
  automatic gate still correctly asks through Open As). The regenerated
  `artifacts/valid-file/Release.json` shows `route=content`,
  `detectedFormat=dae|dxf`.
- Docs: `docs/design/03-file-formats-and-ingestion.md`,
  `docs/design/02-system-architecture.md`, `docs/FORMAT-SUPPORT.md`, and
  ADR-0097.

## Reusable facts

- Signature confidence: `HeadPrefix`, `GltfJsonAsset`, `BinaryStl`,
  `AsciiStlText`, `PlyHeader`, `GlbHeader`, `ThreeDsChunk`,
  `XmlPrefixCaseInsensitive`, `DxfSection`, `IgesRecord`, `BrepHeader`,
  `XbfHeader`, and all ZIP kinds are strong; `HeadPrefixCaseInsensitive`,
  `ObjText`, and `OffHeader` are weak.
- Text probes skip a UTF-8 BOM where appropriate. `HeadPrefix` skips only the
  BOM; `HeadPrefixCaseInsensitive`, `GltfJsonAsset`, `PlyHeader`,
  `AsciiStlText`, `ObjText`, `OffHeader`, and `BrepHeader` also skip leading
  whitespace. `XmlPrefixCaseInsensitive` additionally skips `<?xml ...?>` and
  `<!-- ... -->`.
- IGES requires at least 80 bytes and a line break at byte 80 when more data
  follows. `DBRep_DrawableShape` is 19 characters, not 20.
- `ZipEntryEqualsAndSuffix` uses `bytes` for the equality token and `aux` for
  the suffix; it is only evaluated by `ProbeZipCentralDirectory`.
- The test helper `MakeZip` (in `tests/unit/FormatCatalogTests.cpp`) writes a
  minimal stored ZIP with only central-directory names; `TempFile` gives a
  unique temp path. `PREVIEW3D_REPO_ROOT` is defined by `Tests.Unit.vcxproj`
  and is used by the real-fixture case.

## Gotchas

- `HeadPrefix` deliberately does not skip whitespace; a BOM is tolerated but
  `#usda`/`ISO-10303-21` must still start the document after it. Do not add a
  whitespace skip there without a format-specific reason.
- `LooksLikeBrepHeader` accepts `CASCADE Topology V1, ...` because the comma
  follows the version; it is not a generic token boundary.
- A 3DS main chunk only checks `MM` + a declared length that fits the file.
  A crafted/ambiguous binary can therefore be a 3DS candidate; this is
  advisory and the parser owns acceptance.
- The `[valid-file]` report is regenerated by `[write-valid-file-report]`; do
  not hand-edit `artifacts/valid-file/Release.json`.
- `OffHeader` is weak; `DxfSection` and XML roots are strong. Keep that split
  when adding new textual signatures.
