# T06 — Per-format import options and quality surface

## What landed

- `shared/model-core/include/model_core/ImportOptions.h` is the closed shared
  value:
  - `ImportQuality { Draft, Balanced, Full }`;
  - `ImportWireMode { Fallback, On, Off }` (Fallback is the T05 behaviour);
  - optional `linearDeflection`, `angularDeflection`,
    `unitScaleOverride`; `relativeDeflection` default true;
  - `usdSubdivisionLevel` 0..4;
  - `ImportOptionsTable` with one record per closed format
    (`STEP`, `IGES`, `BREP`, `XBF`, `FCStd`, `USD`);
  - `ParseImportOptionAssignment` for `FORMAT.name=value` (ASCII
    case-insensitive format/name, no trimming);
  - `ValidateImportOptions` rejects unknown/out-of-range/non-finite/
    inapplicable fields;
  - `ImportOptionsPayload` (48 bytes) + `MakeImportOptionsPayload` /
    `ImportOptionsFromPayload`;
  - `ImportOptionsCacheIdentity(format, options)`.
- Protocol: the payload is appended to `ParseStepFileRequest`,
  `ParseCadFileRequest`, `ParseUsdFileRequest` and
  `ParseOpenUsdFileRequest`. Sizes are 96/104/96/96. `version == 0` is the
  legacy zero-filled request; the STEP quality flag bits remain authoritative
  only for that version.
- Broker (`shared/import-broker/src/ImportSession.cpp`):
  - `ImportSessionRequest::importOptions` (optional);
  - validates before launch and returns
    `ImportStage::ValidateOptions` / `ImportProtocolViolation`;
  - writes both the legacy quality flags and the generic payload;
  - sets `ImportSessionResult::importOptionsCacheIdentity`;
  - routes a nonzero USD subdivision level directly to the compatibility host
    when configured.
- STEP/CAD host: `StepHostImport.cpp` re-validates the payload, keeps the flag
  and payload qualities consistent, and maps the options into
  `StepImportPolicy::options`. `StepXdeAdapter.cpp`:
  - explicit relative/absolute deflection and angular override;
  - tri-state wire emission;
  - unit override after authored-unit checks, with compatibility feature
    `kCadFeatureUnitOverrideApplied` (3018).
- USD: `import-worker/src/UsdImportWorker.cpp` and
  `compatibility-host/src/OpenUsdHost.cpp` validate the payload. A nonzero
  subdivision level is `UnsupportedRequiredFeature`; this build has no
  subdivision evaluator.
- Cache: `StepImporterCacheIdentity(format, options)` mixes the generic
  identity with `kStepImporterVersion`; `CacheEntryKey` gained `format` and
  `importOptionsIdentity`; the cache schema is v5 and the header is 96 bytes.
- Viewer: `--import-option` (repeatable), `settings.json` keys
  `import.<FORMAT>.<name>`, and **Settings → Import options…** with CAD
  quality/wires/deflection/unit presets, USD subdivision and reset.
- Docs: `docs/FORMAT-SUPPORT.md`, `README.md`,
  `docs/tasks/0.8.0/README.md`, `docs/design/03-file-formats-and-ingestion.md`,
  ADR-0100.

## Gotchas

- **Rebuild the test project's object directory after changing
  `D3D12ImportBridge.h`.** The `.vcxproj` does not track that header as a
  dependency for every test object, so stale objects linked against the old
  `RunImport` signature and produced LNK2019. Deleting
  `tests/import-isolation/x64/<config>` and rebuilding fixed it.
- **The hostile worker's generic file-request reader must accept both 48 and
  96-byte payloads.** USD now carries the 48-byte option payload; the attack
  modes read the common prefix. Otherwise `--usd-fallback-after-batch` exits
  and the broker reports `WorkerCrashed`.
- `ImportOptionsFromPayload` rejects a non-neutral value behind a clear mask
  bit. `MakeImportOptionsPayload` always sets the mask for quality, wire mode,
  relative mode and subdivision; optional doubles only when present.
- The STEP flag quality and the generic payload quality must agree for a
  version-1 payload; the broker writes both from the same effective record.
- `USD.quality` is not applicable; only `subdivision_level` is accepted for
  USD. `ValidateImportOptions` rejects every other field.
- Do **not** run two `Tests.ImportIsolation.exe` processes in parallel. They
  share the machine-wide worker/compatibility AppContainer profile and worker
  pool names, so a concurrent `[compat]` + `[usd-*]` run produced
  `LaunchWorker`/`InternalImporterFailure` failures for every case; rerunning
  each suite alone passed. Run sandbox suites sequentially.
- The first USD compatibility-host run after a rebuild can transiently fail at
  `LaunchWorker` while the AppContainer profile/host settles; rerunning the
  same case passed. Treat a one-off host launch failure as a test-harness
  race, not a product regression, but re-run before claiming green.
- `std::to_string(double)` is used for settings persistence; it is bounded and
  validated on both save and load, so the tiny settings scanner stays simple.
