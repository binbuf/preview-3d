# T05 — CAD edge and wire geometry

## What landed

- `compatibility-host-step/src/StepXdeAdapter.cpp` now runs a bounded edge
  pass after the face pass when a definition produced no triangles (or the
  internal `readWire` seam is true):
  - face/edge counts are checked **before** `BRepMesh`, so an over-budget edge
    shape fails typed before the kernel allocates polygons;
  - visible `TopAbs_EDGE` shapes are collected into one `TopoDS_Compound` and
    meshed with the same `IMeshTools_Parameters` (deflection, angular
    deflection, min size, parallel policy);
  - `BRep_Tool::Polygon3D` is read per edge, the polygon's `TopLoc_Location`
    is applied exactly like faces, and polylines are expanded into independent
    consecutive pairs (never a strip);
  - non-finite points and zero-length segments are skipped with the bounded
    warning budget; a chunk always has at least one distinct finite segment;
  - vertices are de-indexed `PositionNormalUv0_F32`, grouped by material with
    the same double-origin/cluster scheme as triangles, and emitted as
    `LineList` chunks (one per material/bounded group).
- `GeometryRecord`/`AddGeometry` are topology-aware (`TriangleList` or
  `LineList`); the wire version was not bumped. `AddGeometry` rejects an odd
  de-indexed line vertex count.
- `ScenePlanner` collects authored edge styles from `XCAFDoc_ColorCurv` then
  `XCAFDoc_ColorGen`, with the definition-level shape color as fallback. No
  per-edge material is invented; the neutral line appearance is material 0
  (no `Material` chunk).
- Empty/repair logic:
  - `TryBoundedRepair` now rejects only a shape with neither faces nor edges;
  - the repair trigger is limited to a face-bearing definition that actually
    failed to triangulate;
  - a definition with edges but no faces is visible, and the generation
    succeeds when either triangles or lines were emitted.
- `StepTessellationProfile` v7 adds `maxLineSegmentsPerDefinition =
  4'000'000` and `chunkLineSegments = 65'536`. Existing
  `maxEdgesPerDefinition = 2'000'000` still applies. Over-budget shapes fail
  `TessellationFailed`.
- `StepImportPolicy::readWire` is the dormant T06 seam. T05 keeps it false, so
  solids never get a default edge overlay.
- `[cad-wires]` cases in `tests/import-isolation/CadHostTests.cpp` cover:
  - wireframe STEP, IGES, BREP and FCStd: `LineList` chunks, even index count,
    finite vertices/origins/bounds, verified bounds, no triangles/points, no
    invented materials, positive world span;
  - solid STEP, IGES, BREP and FCStd: triangles and zero `LineList` chunks;
  - over-budget edge and segment definitions: typed `TessellationFailed` via
    the test-only tiny-budget flag.
- Valid-file manifest flips: `wire-step` and `wire-iges` are `opened/lines`;
  `wire-brep` and `wire-fcstd` are `degraded/lines` because BREP/FCStd always
  carry their units-assumption compatibility record. `[valid-file]` passes in
  Release and Debug.
- Docs: `docs/FORMAT-SUPPORT.md`, `docs/design/03-file-formats-and-ingestion.md`,
  ADR-0099, and `tests/fixtures/valid-file/README.md`.

## Fixtures

Reused the T01 generated wire fixtures under `tests/fixtures/valid-file/`:

- `wire.step` — AP214 `GEOMETRIC_CURVE_SET`/`POLYLINE`, no faces.
- `wire.igs` — two type-110 line entities. The generator's global-section
  Hollerith lengths were corrected to `8Hwire.igs` and `9HPreview3D`; the old
  `13Hwire.igs` consumed the comma and shifted the unit flag, which made the
  pinned IGES parser report a non-millimetre unit.
- `wire.brep` — `CASCADE Topology` compound of two edges.
- `wire.FCStd` — ZIP package with the wire `PartShape.brp`.

Observed normalized segment counts in the Release valid-file report: STEP 16,
IGES 2, BREP 2, FCStd 2. All four open with `LineList` and verified bounds.

Regenerate only the IGES fixture with:

```powershell
python -c "import importlib.util, pathlib; spec=importlib.util.spec_from_file_location('g', r'tests/fixtures/valid-file/generate_fixtures.py'); g=importlib.util.module_from_spec(spec); spec.loader.exec_module(g); pathlib.Path(r'tests/fixtures/valid-file/wire.igs').write_bytes(g.iges_wire().encode('utf-8'))"
```

fresh ZIP timestamp.

## Gotchas

- **`ImportSessionRequest request;` left the new bool uninitialized** in this
  toolchain (the debug print showed arbitrary bytes such as 24/64/109 even
  immediately after construction, while `CHECK_FALSE` was constant-folded).
  Use `ImportSessionRequest request{};` for value-initialization. The viewer
  (`D3D12ImportBridge.cpp`) and all test helpers were changed to `{}` so the
  tiny-budget flag cannot leak into product or unrelated test requests.
- `BRepMesh_IncrementalMesh` only discretizes edges as part of a shape, so the
  edge pass builds one `TopoDS_Compound` of the visible edges (the F3D
  reference does the same). It does not mesh a bare edge list.
- `Poly_Polygon3D` may already be present from the face pass; reading it after
  the edge compound mesh is harmless and preserves authored polygons.
- The validator requires `LineList.indexCount` even and every index <
  `vertexCount`; the de-indexed identity-index scheme satisfies both.
- The BREP/FCStd valid-file entries are `degraded`, not `opened`, because the
  adapter always records the unit assumption. This is existing T08/T09
  behavior, not a T05 regression.

## Follow-ups

- T06: expose the user-facing `read_wire` option and map it to
  `StepImportPolicy::readWire`. When true, the mesher already runs the edge
  pass for solid definitions and emits both triangle and line chunks; T06
  should decide the default, cache identity, UI, and whether face-boundary
  edges need a separate style policy.
- A colored wire fixture (STEP `STYLED_ITEM`/`CURVE_STYLE` on the polyline)
  would exercise the authored-edge-color path. The current fixtures are
  intentionally uncolored, and `[cad-wires]` asserts no invented material.
- USD curves/NURBS remain a separate limitation; T05 only covers the OCCT CAD
  host.
- T09/T10: keep the support matrix and qualification evidence in sync with the
  new `opened/lines` and `degraded/lines` wire entries.
