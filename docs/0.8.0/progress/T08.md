## Fixtures that actually diverge

- glTF: `required-extension.gltf` requires `KHR_implicit_shapes`; the native
  adapter returns `UnsupportedRequiredFeature` before fastgltf, Assimp ignores
  the unknown required name and opens the core triangle.
- 3MF: `required-extension.3mf` declares the Slice namespace as required; the
  native display scan returns `UnsupportedRequiredFeature`, Assimp reads the
  core mesh. `InspectThreeMfOpc` does not reject required extensions.
- OBJ: `missing-vt.obj` (`v` plus `f 1/1 2/2 3/3` with no `vt`) makes ufbx
  report no geometry (`EmptyGeometry`); Assimp keeps the position-only
  triangle.
- FBX: `line-only.fbx` (2-vertex polygon) makes ufbx report `EmptyGeometry`;
  Assimp opens it as a `LineList`. The broker only accepts it because the FBX
  wire unit policy is now metres (see below).
- `line-only.obj` is **not** usable as a fallback fixture: Assimp's
  `ValidateDataStructure` rejects a 2-index `f` face because the OBJ importer
  marks the mesh `TRIANGLE`. Use `missing-vt.obj` instead.

## Gotchas

- **Unit policy is enforced by the broker validator.** `SceneUnitsAndUpAxisAllowed`
  requires glTF/GLB and FBX to report `metersPerUnit == 1.0` and Y up; OBJ is
  0.0 with Y/Unknown; 3MF is unconstrained. An Assimp compatibility route that
  reports 0 for glTF/FBX fails at `ImportSession` stage `ValidateSection` with
  `MalformedData` even though the worker succeeded. Assimp's FBX importer bakes
  the authored `UnitScaleFactor` into the root transform, so the geometry is in
  centimetres; the adapter applies a 0.01 root scale to report metres.
- **The worker's stderr is null** (`SandboxLauncher` sets `hStdError=nullptr`),
  so a worker-side `fprintf` is invisible to the test console. Debug adapter
  failures with the fuzz target (in-process) or with the typed result.
- **The fuzz target needs `ThreeMfOpcPreflight.cpp`** now that the adapter calls
  `InspectThreeMfOpc`; it is already added to `AssimpFuzz.vcxproj`.
- `AssimpFuzz` shares `tests/fuzz/x64/<config>` with the other fuzz projects
  (MSB8028 warning). Build one target at a time.
- The compatibility fallback clears `workerArgumentsOverride`, so a test that
  needs an attack mode to survive into the compatibility attempt cannot use
  that seam. The policy tests use real fixtures instead.
- A forced reader sets `allowAutomaticReaderFallback=false`; the failure card
  offer is derived in `D3D12ImportBridge` from the closed eligible set and the
  family's compatibility reader. Do not add a second fallback in the UI.

## Follow-ups

- The compatibility FBX route applies Assimp's app scale but does not reproduce
  the native FBX adapter's axis conversion (`target_axes`), pivot/inherit-mode
  handling, material texture slots, or static-pose evaluation. It is an
  openability fallback, not a fidelity replacement.
- Assimp's OBJ importer does not support a 2-index `f` face under
  `ValidateDataStructure`; if a future real-world OBJ needs that, consider a
  product-owned face pre-normalization or a dedicated admission rejection.
- Add a real-world native-rejected OBJ/FBX sample to T09 once one is available;
  the current fixtures are repository-owned synthetic divergences.
- Consider surfacing the fallback reader in the Open As menu state after a
  successful automatic fallback (today the info panel and notice name it, but
  the menu still shows the family default).
